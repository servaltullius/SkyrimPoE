# 7단계 PoE2 전환 계획

- **상태**: 2판(2026-11-24, Claude 작성). 1판을 Codex 교차 검토(gpt-6.2-astra, 판정 "수정 후 재검토", 차단 6·높음 다수)로 고쳤습니다(12장). 2판은 재검토 전입니다. 9장의 U-1·U-2·U-16·U-19는 결정 190~193으로 확정됐고(2026-11-24) 나머지 사용자 결정이 남았습니다.
- **근거 결정**: 189(기준 게임을 PoE2로, 확정). 이미 PoE2에서 빌린 구조 42(스킬 젬이 보조 소켓을 가짐, 장비에 젬 소켓 없음), 43(Spirit이라는 별도 자원), 44(플라스크 대신 참), 88(스킬 칸 9개)는 유지합니다. 다만 그 결정 안의 수치(161의 Spirit 획득량, 162의 참 6종)는 5장에서 다시 봅니다.
- **기준 데이터**: PoE2용 PoB 0.23.1(`G:\poe\PathOfBuilding-PoE2-0.23.1\`, 게임 0.5 데이터, 트리 `TreeData/0_5`). 이 PoB의 `manifest.xml`에 파일별 해시가 있어 판 기록에 씁니다.
- **1.0**: GGG가 2026-11-06에 PoE2 1.0 출시(2026-12-11, PST)를 발표했습니다. 함께 발표된 변경은 보조 젬 대폭 재조정, 트리의 새 스탯 수백 개와 주얼 소켓 이동, 석궁 재장전 변경, 고유 아이템 70종 이상 개편입니다(Steam 공지, 12장 출처). 1.0용 PoB가 언제 어디까지 나올지는 모릅니다.
- **사이클론**: 사용자 판단으로 유지합니다(2026-11-24, "간판 스킬이라 1.0에 나올 것"). 게임 디렉터 인터뷰에 사이클론과 자세 연계 설계 언급이 있습니다(12장 출처). 0.5 데이터에는 없으므로 1.0 데이터가 나올 때까지 지금의 PoE1 3.30 데이터를 **예외로** 씁니다(2장 원칙 7).
- **조사**: 3장의 수치는 2026-11-24 PoB 데이터 파일을 직접 읽어 잰 것이고, Codex가 표본 대조했습니다. PoB 개발자가 쓴 공식은 [PoB], 확인하지 못한 것은 [미확인]입니다. 컴파일러를 PoE2 데이터로 실제로 돌려 보지는 않았습니다.

## 1. 목표

1. 스킬·보조 젬, 패시브 트리, 전직, 아이템·어픽스, 화폐·제작, 전투 규칙(방어·상태 이상), 몬스터 수치, 엔드게임의 기준을 PoE2로 바꿉니다.
2. PoB-PoE2 데이터를 **최대한 많이 뽑아 원천 팩으로 남깁니다**(사용자 요청). 스카이림에 넣으려면 어차피 가공해야 하므로 뽑기와 가공을 나눕니다(원칙 1).
3. 1.0 반영을 "다시 뽑기 → 차이 보고 → 의미가 바뀐 것만 사람이 판정 → 다시 만들기"로 만듭니다(8장). 의미가 바뀐 것은 해당 마일스톤을 다시 엽니다.
4. 스카이림 쪽 기반(전투 훅의 틀, 저장의 틀, UI 연결, 던전 복제와 이동, ES 표시, 선택 연동, SE 지원)은 유지합니다.

넣지 않는 것: PoE1 데이터를 함께 유지하는 이중 지원, 1.0 이전에 0.5 수치를 손으로 다듬는 밸런스 작업.

## 2. 원칙

1. **뽑기와 가공을 나눕니다.**
   - **원천 팩**: PoB-PoE2 파일을 가공 없이, 필드를 버리지 않고 JSON으로 뽑습니다. 각 항목에 원본 판·파일·키를 붙입니다. 대상은 `Gems.lua`, `Skills/*.lua`(statSets, 숨은 추가 효과, `statMap`이 함수인 경우는 "미지원" 표시와 원문 보존), 트리, `Bases/*.lua`(PoB가 실제로 읽는 목록 기준과 파일 선언 기준을 둘 다 기록), `ModItem`·`ModItemExclusive`·`ModVeiled`·`ModIncursionLimb`·`ModCharm`·`ModFlask`·`ModJewel`·`ModCorrupted`·`ModRunes`·`Essence`, `Uniques`, `Misc.lua`, `QuestRewards.lua`, 그리고 계산 공식이 든 `Modules/Data.lua`·`CalcDefence.lua`·`CalcOffence.lua`의 판 정보입니다.
   - **게임 팩**: 원천 팩에서 고른 것만 스카이림 단위로 바꾸고 한국어 이름을 붙여 플러그인이 읽게 만듭니다. 무엇을 고를지는 선택 목록 파일(사람이 고치는 JSON)에 둡니다.
   - 컴파일러는 `extract`(PoB → 원천 팩)와 `build`(원천 팩 + 선택 목록 → 게임 팩)로 나눕니다.
2. **원본 키와 우리 ID를 나눕니다.** PoE 판이 바뀌면 같은 번호가 다른 뜻이 됩니다(실례: 트리 노드 10079는 0.4에서 "Energy Shield Recharge", 0.5에서 "Mana Regeneration", `TreeData/0_4/tree.lua:37961`, `0_5/tree.lua:39998`). 그래서:
   - 세이브와 ESP는 우리 내부 ID만 씁니다. 원본 키는 선택 목록에서 우리 ID로 대응시킵니다.
   - 판 비교 도구는 키의 존재만이 아니라 **의미 지문**(이름, 스탯 문장, 연결, 태그)을 비교해 유지·이름 변경·의미 변경·분할·병합·삭제로 분류합니다.
   - 의미가 바뀐 원본 키에 걸린 우리 ID는 저장된 할당을 그대로 복원하지 않습니다(9장 U-1의 정책대로 환불 또는 제거).
3. **판을 기록하고, 실제 배포본에서 판을 검사합니다.**
   - 모든 팩에 PoB 판, 게임 판, 원본 파일 해시, 추출기 스키마 판을 적습니다.
   - DLL은 지금 `core_3_30.json`·`tree_3_30.json`·`items_3_30.json` 이름을 코드에 박아 엽니다(`plugin/src/main.cpp:44-46`). CMake도 이 세 파일을 복사하고 트리에서 UI용 `tree-data.js`를 만듭니다(`plugin/CMakeLists.txt:226-242`). 파일 이름에서 판을 빼고, DLL이 팩 안의 판 정보를 읽어 **팩끼리·UI 트리·ESP와 판이 맞는지** 확인한 뒤 어긋나면 기능을 끄고 알립니다.
   - 배포 검사: 깨끗한 설치, 업그레이드 설치(기존 배치는 덧쓰기라 옛 파일이 남음, `plugin/build.bat:64`), 일부만 옛 판인 설치를 확인합니다.
4. **PoE 수치를 코드에 박지 않되, 공식과 환산을 나눕니다.**
   - `Misc.lua`·`Modules/Data.lua`의 상수는 규칙 팩으로 뽑습니다.
   - 공식(방어도, 명중, 편향, 상태 이상 누적)은 PoB 계산 모듈에 있습니다. `Modules`만 바뀌는 판은 원천 팩 차이가 0이어도 결과가 달라지므로, 계산 모듈 파일의 해시도 판 기록에 넣고 바뀌면 P2를 다시 엽니다.
   - 시험 기대값은 둘로 나눕니다: PoB 공식의 기대값, 우리 스카이림 환산 정책(`DamageConversion`이 맡는 PoE↔스카이림 단위 환산)의 기대값.
5. **문장 어휘는 적용률로 관리하되 기준을 정합니다.** 지금 트리 컴파일러는 아는 줄이 하나라도 있으면 노드를 "구현"으로 치고, 아이템은 모든 줄을 알아야 롤 대상으로 삼습니다(`compile_tree.py:525-552`, `compile_items.py:353-364`). PoE2에서는 노드·어픽스마다 완전/부분/미지원을 나눠 보고하고, 핵심 키스톤·고유 효과는 목록으로 따로 봅니다. 완료 기준은 보고서가 나오는 것이 아니라 마일스톤마다 정한 적용률입니다(6장).
6. **공개 범위를 셋으로 나눕니다.** 원본 데이터에는 GGG 저작권 표기가 있습니다(예: `Data/Gems.lua:2`). PoB 라이선스는 고지 보존을 요구합니다. 결정 27·28(이름·트리 사용, 비수익 공개)은 원문 설명·번역 묶음·판별 원천 전체의 공개까지 정한 것이 아닙니다. 그래서:
   - **로컬 추출**: 전부 뽑습니다(저장소 밖이나 `.gitignore`).
   - **공개 저장소**: 9장 U-2에서 정한 필드만 넣습니다.
   - **배포 게임 팩**: 플러그인이 쓰는 필드와 필요한 고지만 넣습니다.
7. **예외 데이터는 표시하고 시험으로 지웁니다.** 사이클론처럼 0.5에 없어 PoE1 3.30 데이터를 빌리는 항목은 게임 팩에 `borrowedFrom: "poe1-3.30"`을 붙입니다. 1.0 반영 뒤 빌린 항목이 남아 있으면 시험이 실패하게 합니다.
8. **결정은 쓰일 때 기준 문서에 반영합니다.** P8에서 한꺼번에 다시 쓰지 않습니다. 각 마일스톤이 바꾼 결정은 그 마일스톤 안에서 설계-현황 2장과 통합 설계서에 반영합니다.

### 3.5 엔드게임과 화폐

- **웨이스톤**: 티어, 지도 어픽스, 사망 규칙이 PoB 데이터에 없습니다. `ModMap.lua` 74개는 사람이 쓴 파일이고 PoE1 효과가 섞여 있습니다. 공개 자료로 조사하고 우리 설계로 정해야 합니다.
- **화폐**: PoB에 화폐 데이터가 없어 문자열로만 근거를 찾았습니다.
  - 기본 이름(진화·확장 등): `TradeQueryGenerator.lua:760-766`
  - Greater/Perfect 등급 표기: `ModScalability.lua`, `TradeSiteStats.lua`
  - 확인된 것: Transmutation·Augmentation·Regal·Chaos·Exalted(등급 포함), Alchemy, Vaal, Divine, Annulment, Chance, Artificer's Orb, Gemcutter's Prism, Glassblower's Bauble, Mirror
  - 2026-11-12 조사에서 없다고 분류한 것: Scouring, Chromatic, Fusing
  - [미확인]: Alteration, Regret, Scroll of Wisdom, Jeweller's 등급
  - 문자열이 있다고 획득률이나 제작 효과가 확인되는 것은 아닙니다. 예를 들어 지금 Chaos는 희귀 어픽스 전체를 다시 굴리는데, PoE2 Chaos는 하나를 바꿉니다.
- **한국어 이름**: 한글판 PoB의 PoE2 추가 번역(`POE2 0.2.1 번역 추가.csv:3198-3201`)에 Augmentation·Transmutation·Annulment 등 일부가 있습니다(결정 188에서 대조함). 나머지 출처는 U-14로 정합니다.

## 7. 6.5단계와의 관계

- **끝난 것**: E(적 ES 표시), T(TrueHUD).
- **결정 183의 순서는 유지합니다**: AE의 I·G를 마친 뒤 AE PR, 그 뒤 HEDR·SE입니다. 1판에서 "H·S를 지금 함께"라고 쓴 것은 183과 어긋나 고쳤습니다. H는 최종 ESP를, S는 공용 코드와 실제 훅을 검사하므로 7단계가 ESP·코드를 바꾼 뒤 다시 확인해야 합니다.
- **충돌**: 6.5의 G6(Grid PNG 아이콘)은 I1 원본과 162폼 매핑을 씁니다. 7단계는 그 폼 구성을 바꿉니다. 결정 193으로 (나)를 골랐습니다(2026-11-24):
  - (가) 6.5 AE판을 지금의 162폼으로 마무리하고 PR한 뒤 7단계를 시작합니다.
  - (나) I·G6을 7단계 뒤로 옮기고, 6.5는 E·T까지로 PR합니다.
- **아이콘**: 공통 화폐 그림은 다시 쓸 수 있습니다. 최종 폼·등급·파일 이름 매핑은 P5에서 정합니다.

## 8. 1.0 반영 절차

1. 게임 출시일(12-11)과 1.0용 PoB 확보일을 구분합니다. 1.0 PoB가 늦거나 일부만 지원하면 0.5를 기준으로 유지하고, 1.0 지원이 트리·젬·아이템 세 축을 모두 덮을 때 옮깁니다.
2. 1.0 PoB를 새 폴더에 풉니다(실행하지 않음). 설계-현황 6장에 경로를 적습니다.
3. `extract`로 1.0 원천 팩을 만들고, 판 비교 도구로 0.5와의 차이 보고서를 만듭니다. 계산 모듈 해시가 바뀌었으면 P2를 다시 엽니다.
4. 보고서를 분류합니다.
   - 수치만 바뀐 것: `build`를 다시 돌려 끝냅니다.
   - 의미·그래프·행동이 바뀐 것(노드 뜻, 연결, 젬 행동, 새 메커니즘): 해당 마일스톤(P2~P6)과 ESP·UI·시험을 다시 엽니다.
   - 우리 ID에 걸린 원본 키가 의미 변경이면 U-1의 정책(환불·제거)을 적용합니다.
5. 빌린 데이터(사이클론)를 1.0 데이터로 바꾸고 빌린 항목 0을 시험으로 확인합니다. 1.0에도 사이클론이 없으면 사용자에게 다시 묻습니다.
6. 문제가 생기면 마지막 정상 게임 팩(0.5)으로 돌아갈 수 있게 판별 게임 팩을 보존합니다.
7. 기준 데이터를 1.0으로 바꾸는 결정을 설계-현황에 적습니다.
