## 5. 순서와 의존

```
R0 ─┬─ R1 도구 ─ E 실험(실행 1) ─┬─ R4 지도 공간 ─ R5 결함 ─ R6 시험(실행 2·3) ─ R7
    └─ R2 브랜치 이전 ─ R3 난이도 ─┘
```

- R1·E와 R2·R3은 서로 다른 파일을 고치므로 함께 진행할 수 있습니다. R1은 C# 도구와 시험 DLL이고, R2·R3은 6단계 DLL입니다.
  - 문서는 두 줄기가 모두 고치므로, R0의 커밋 뒤에 갈라지고 문서 수정은 한쪽에서만 합니다.
- R4와 R5의 D-1은 E의 결과(정리·초기화·입장·출구 방법)와 R1의 목록 파일 형식이 정해져야 시작합니다.
- 실행 1에서는 브랜치의 정리 경로를 쓰지 않습니다. 그래서 알려진 크래시 호출을 실행하지 않습니다.

## 6. 남는 미확인

이 계획을 끝까지 해도 확인되지 않는 것입니다.
- SE 1.5.97에서의 동작(6.5단계)

- 공유 기본 객체·스크립트를 다른 모드가 바꿀 때 복제본에 주는 영향. Skyrim.esm만 마스터로 둬도 기본 객체는 공유하므로, 격리되지 않습니다.
