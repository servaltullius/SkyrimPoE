## 1. 아키텍처 개요 및 모듈 경계

```text
[오프라인 빌드 도구]
  tools/compiler/compile_items.py
    └─ PoB 2.68.1 ModExplicit.lua + Data/Bases/*.lua ──▶ data/packs/items_3_30.json

  esp/records.json (houseCARL) ────────────────────────▶ esp/SkyrimPoE.esp (0x800.., ~125폼 ESL)

[Core 계층: 엔진 무의존, C++ 단위 테스트 100%]
  ItemData          : items_3_30.json 로더, PoE first-match-wins weightKey 가중치 추첨기
  ItemAffixParser   : isLocal 플래그 기반 로컬(무기/방어구) + 글로벌 스탯 분리 합산기
  ItemCrafting      : 12종 오브 상태 머신(주입 가능 RNG), 3P/3S·group 중복 배제·iLvl 티어 필터
  ItemFormatter     : UI 비종속 아이템 카드/설명 줄 생성기(Prisma UI 즉시 사용, Grid/SkyUI 재사용 대비)
  LootTable         : 유효 몬스터 레벨 → 5티어 토큰/12종 오브 드랍 확률 테이블
  StatEngine (확장) : 논리 8칸 장비 합산 + 고정점(Fixed-Point) 능력치 요구치 수렴(최대 8회 반복)
  PassiveTree (확장): 후회의 오브 비용 계산기(일반/마스터리 1개, 전직 5개, 고아 마스터리 동반 비용 포함)

[Runtime 계층: AE 1.6.1170 + CommonLibSSE-NG v16.4.0]
  UniqueIdUtil      : 공용 CreateGameExtraDataList(듀얼 SE+AE 안전) + 비중복 UID 대역 할당기
                      (인벤토리 공용 0x7000..0x7EFF / 젬 바닥 0x7F00..0xBFFF / 아이템 바닥 0xC000..0xFFFD)
  ItemTracker       : 프로토타입 5 검증 방식 — TESUniqueIDChangeEvent(이동/삭제/바닥 스탬프 결정 123 예외)

  EquipmentSync     : ExtraWorn/ExtraWornLeft 직접 스캔 → 논리 8칸 단일 귀속 → SaveLoad::SyncStateToStatEngine 병합
  CraftingRuntime   : SaveLoad::RunSerializedTransaction + 주 갱신 단일 틱 원자 거래
  WorldDropTracker  : 자체 바닥 드랍 추적기(Death Drop Overhaul 미의존) + 'WDRP' v1 복원 + 고아 빛기둥 스윕
  SaveLoad (확장)   : 'ITEM' v1 + 'WDRP' v1 추가('CORE' v2 / 'GKEY' v1 / 'TREE' v1 완전 하위 호환)
  UiBridge (확장)   : 단일 Prisma UI 뷰 3번째 탭 `장비·제작` (`O` 키) + 패시브 탭 후회의 오브 잔량 표시
  AutoTest (확장)   : 시나리오 E (`E1~E8`)
```

## 2. 마일스톤 및 배치 구성 (3개 배치, 배치마다 독립 검수)

### 배치 1: 오프라인 데이터 컴파일러 + Core 아이템·제작·드랍·스탯 엔진 (`S4-M1 ~ S4-M3`)

#### `S4-M1`: PoB 3.30 어픽스 컴파일러 (`tools/compiler/compile_items.py`) + 젬 능력치 요구치 확장 (`compile_stage2.py`)
- **입력**:
  - `G:\poe\PathOfBuilding-2.68.1\Data\ModExplicit.lua` (4,222건 전수 파싱)
  - `G:\poe\PathOfBuilding-2.68.1\Data\Bases\{sword,axe,mace,dagger,bow,staff,helmet,body,gloves,boots,shield,amulet,ring}.lua` (티어·iLvl별 기본 방어/공격/요구 능력치 커브 추출)
  - `G:\poe\PathOfBuilding-2.68.1\Data\Gems.lua` (`compile_stage2.py` 확장: 기존 9개 젬의 레벨별 `reqStr`/`reqDex`/`reqInt` 추가, 기존 스키마 하위 호환)
- **필터 및 정규화 규칙 (검수 C1 반영)**:
  1. **영향력 접미사 9종만 제거**(`_shaper`, `_elder`, `_crusader`, `_adjudicator`, `_eyrie`, `_basilisk`, `_warlord`, `_hunter`, `_redeemer`).
  2. **비영향력 `0`-오버라이드 태그와 원본 순서 절대 보존**: `attack_staff=0`, `attack_dagger=0`, `focus=0`, `ranged=0`, `fishing_rod=0`, `weapon=0` 등 차단 항목을 제거하지 않고 원본 순서 그대로 유지해 PoE first-match-wins 평가가 100% 정확히 작동하게 함.
  3. **방패·원거리·근접 확장 태그 완전 포함**: `str_shield`, `dex_shield`, `focus`, `str_dex_shield`, `str_int_shield`, `dex_int_shield`, `ranged`, `attack_dagger`, `attack_staff`, `warstaff`를 포함해 방패 막기(`LocalIncreasedBlockPercentage`, `str_shield`), ES 방패 주문력(`focus`), 활 상위 공속(`ranged`)이 빠짐없이 롤링되도록 보장.
  4. **값 범위 정규화 및 소수점 지원**:
     - `-(8-6)` 같은 역순 범위(`min > max`)는 컴파일 시 `(min, max)` 오름차순으로 정규화(`min <= max` 불변식).
     - 소수점 범위(`(0.2-0.4)%` 등)는 `isFloat: true`, `step: 0.1` 메타데이터와 `double` 범위로 저장해 정밀도 손실 방지.
     - 다중 줄 어픽스 및 고정 숫자+범위 혼합 줄(`Adds 1 to (2-3) Physical Damage`)은 줄별 `ranges: [[min, max, isFloat], ...]` 배열로 정확히 파싱하고 평탄화 인덱스(`values[0..N-1]`)를 1:1 매핑.
  5. **`isLocal` 플래그 명시 출력 (검수 m1 반영)**: PoB 어픽스 ID(`Local...` 접두 및 무기/방어구 전용 로컬 모디파이어 판정)를 컴파일 시 `isLocal: bool`로 기록해 런타임 문자열 휴리스틱 오판을 원천 차단.
  6. **4단계 전투 지원 선별 (`rollable: bool`)**: 4단계 전투·방어·능력치 엔진이 실제 적용하는 어픽스만 `rollable: true`로 표기(소환수·토템·덫/지뢰·플라스크·젬레벨 전용 등은 `rollable: false`)해 "붙었는데 무효과인 어픽스" 롤링을 방지.
- **출력 스키마 (`data/packs/items_3_30.json`)**:
  - `version`: `"3.30"`, `schemaVersion`: `1`
  - `affixes[]`: `{ id, type ("Prefix"|"Suffix"), affixName, group, level (iLvl), tier (1=최고 티어), isLocal, rollable, lines: [{ template, koTemplate, ranges: [[min, max, isFloat], ...] }], weights: [[key, val], ...], tags: [...] }`
  - `tiers`: 5단계 아이템 레벨 티어 (`T1: 1~20`, `T2: 21~40`, `T3: 41~60`, `T4: 61~80`, `T5: 81~100`)
  - `currencies`: 12종 오브 메타데이터(`id`, `enName`, `koName`, `koDesc`, `dropWeight`, `worldDropTier`)
  - `baseArmorCurves` / `baseWeaponCurves`: PoB `Data/Bases/*.lua` 기반 `(slotGroup, defenseSubtype/weaponType, itemLevel)` → `{ baseArmour, baseEvasion, baseEs, baseBlockPct, basePhysMin, basePhysMax, baseCritPct, baseAps, reqLevel, reqStr, reqDex, reqInt }`
- **검증**: `tools/compiler/test_items_compiler.py` (first-match-wins 0-오버라이드 검증, `str_shield`/`focus`/`ranged` 롤링 검증, 역순/소수점/다중 줄 파싱 검증, `isLocal` 분류 검증, `Data/Bases` 커브 단조 증가 검증).

#### `S4-M2`: Core 아이템 데이터·어픽스 파서·제작 엔진·포맷터·드랍 테이블
- **신규 파일 (`plugin/src/core/`)**:
  - `ItemTypes.h`:
    - `EquipSlot` enum (8칸 고정, 결정 156): `MainHand = 0, OffHand = 1, Helmet = 2, Body = 3, Gloves = 4, Boots = 5, Amulet = 6, Ring1 = 7, Count = 8`.
    - `ItemRarity` enum: `Normal = 0, Magic = 1, Rare = 2`.
    - `CurrencyKind` enum (12종, 결정 158): `ScrollOfWisdom, Transmutation, Augmentation, Alteration, Regal, Alchemy, Chaos, Exalted, Scouring, Divine, Regret, Jeweller`.
    - `TokenSlotGroup` enum (8부위, 결정 157): `OneHandWeapon, TwoHandOrRangedWeapon, Shield, Helmet, Body, Gloves, Boots, Jewelry`.
    - `DefenseSubtype` enum: `None = 0, Armour (Str) = 1, Evasion (Dex) = 2, EnergyShield (Int) = 3`.
    - `RolledAffix`: `{ affixId, values: vector<double> }` (`values[k]`는 `lines`의 모든 `ranges`를 순서대로 평탄화한 값).
    - `PoEItemRecord`: `{ baseFormId, rarity, itemLevel, slotGroup, defenseSubtype, weaponTag, affixes: vector<RolledAffix> }`.
  - `ItemData.h/.cpp`:
    - `items_3_30.json` 로드 및 인덱싱(`byId_`, `prefixes_`, `suffixes_`, `baseArmorCurves_`, `baseWeaponCurves_`).
    - **PoE First-Match-Wins 가중치 평가기**: `ResolveWeight(affix, itemTags)` — `affix.weights`를 앞에서부터 순회하며 `itemTags`에 포함된 **첫 번째 키**의 `weightVal`을 즉시 반환(`0`이면 즉시 `0` 반환).
    - `BuildItemTags(slotGroup, defenseSubtype, weaponTag)` — PoB `Data/Bases/*.lua` 기준 태그 목록 생성(예: 중갑 방패 → `["str_shield", "shield", "str_armour", "armour", "default"]`, 로브 방패/포커스 → `["focus", "shield", "int_armour", "armour", "default"]`, 한손 단검 → `["attack_dagger", "dagger", "one_hand_weapon", "weapon", "default"]`, 활 → `["bow", "ranged", "two_hand_weapon", "weapon", "default"]`, 근접 양손 지팡이 → `["attack_staff", "warstaff", "staff", "two_hand_weapon", "weapon", "default"]`).
    - 후보 필터링: `affix.rollable && affix.level <= itemLevel && ResolveWeight > 0 && !usedGroups.contains(affix.group)`.
  - `ItemAffixParser.h/.cpp`:
    - 컴파일러의 `isLocal` 플래그를 기준으로 **로컬 모디파이어**(해당 장비의 `+방어도/회피/ES`, `% 증가 방어력`, `+방패 막기`, 무기 `+물리/화염/냉기/번개/카오스 피해`, `% 증가 무기 물리 피해`, `% 증가 무기 공속/치명타`)와 **글로벌 모디파이어**(`+힘/민첩/지능/모든 능력치`, `+생명력/마나/ES`, `% 증가 생명/마나/ES`, 화염/냉기/번개/카오스/모든 원소 저항, `% 증가 물리/원소/주문/근접 피해`, 글로벌 공속/시속/치명타 확률·배율, 주문 억제, 막기, 생명/마나 재생)를 엄격히 분리.
    - 로컬 모디파이어는 해당 장비 베이스에만 `(base + localFlat) * (1 + localInc/100)` 적용 후 전역 합산.
  - `ItemCrafting.h/.cpp` (검수 M5 반영):
    - 주입 가능 RNG를 받는 순수 제작 엔진:
      - `IdentifyToken(tier, rarity, slotGroup, defenseSubtype, weaponTag, exileLevel, data, rng)` → iLvl을 티어 구간 `[tierMin, tierMax]` 내부로 고정(`std::clamp(exileLevel, tierMin, tierMax)`). 매직 1~2개(최대 1P+1S), 희귀 4~6개(매 추첨마다 3P/3S 상한 및 `group` 중복 배제 강제; 저레벨에서 가용 고유 `group`이 목표 수보다 적으면 무한 루프 없이 가용 최대치로 정상 종료).
      - `ApplyOrb(orbKind, PoEItemRecord& item, itemTags, data, rng)` → `CraftResult` (`Ok`, `InvalidRarity`, `AffixLimitReached`, `NoEligibleAffix`, `NoOp`, `UnsupportedOrb`):
        - `Transmutation`: Normal → Magic (1~2개)
        - `Augmentation`: Magic(어픽스 1개) → 빈 P 또는 S 자리에 1개 추가
        - `Alteration`: Magic → 초기화 후 Magic(1~2개) 재롤
        - `Regal`: Magic → Rare + 빈 P/S 자리에 1개 추가(기존 유지)
        - `Alchemy`: Normal → Rare(4~6개, 3P/3S 강제)
        - `Chaos`: Rare → 초기화 후 Rare(4~6개, 3P/3S 강제)
        - `Exalted`: Rare에서 `prefixCount < 3` 또는 `suffixCount < 3`인 열린 쪽 풀에서만 추첨해 1개 추가(둘 다 3이면 `AffixLimitReached`)
        - `Scouring`: Magic/Rare → Normal(어픽스 전부 제거, **`itemLevel`·`slotGroup`·`defenseSubtype`은 절대 보존 — 검수 M1 반영**)
        - `Divine`: 어픽스 0개이거나 모든 어픽스의 모든 범위가 고정값(`min == max`)이면 `NoOp` 반환(오브 미차감); 그렇지 않으면 각 `values[k]`를 범위 내 재롤
      - `ApplyJewellerToGem(GemInstance& gem)`: `gem.kind != GemKind::Support` 확인(`Support`이면 `UnsupportedTarget`), `socketCount < kMaxGemSockets(5)`이면 `+1` 확정 증가(5소켓이면 `AlreadyMaxSockets`). 대상은 **장착 스킬 젬·발동 젬 및 발동 젬 안에 담긴 주문 젬 전체**(결정 132). *(초기 젬 소켓 수: 스타터 지급 젬은 기존 2단계 `starterSockets = 3` 유지[3→4→5], 추후 드랍 Lv1 젬은 2소켓[2→5]으로 통일)*
  - `ItemFormatter.h/.cpp`:
    - UI 비종속 포맷터(결정 160): `FormatItem(record, baseName, equipSlot, reqCheck, itemData)` → `FormattedItemCard` (제목, 희귀도 코드+텍스트 배지 `[일반]`/`[매직]`/`[희귀]`, iLvl, 부위, 로컬 방어/공격 수치, 요구 능력치 충족/미달, 접두/접미 티어 `[접두 T2]` + 한글 스탯 줄 목록).
  - `LootTable.h/.cpp`:
    - `RollKillDrops(effectiveMonsterLevel, isBoss, isDragon, config, rng)` → `effectiveMonsterLevel` 기반 5티어 결정(`1..20→T1`, `21..40→T2`, `41..60→T3`, `61..80→T4`, `81+→T5`), 일반/보스/드래곤별 토큰·오브 드랍 확률(INI 설정).
