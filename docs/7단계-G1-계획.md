# 7단계 G1 세대 1 활성화 계획

3판, 2026-11-26, Claude. 1판을 Codex가 교차 검토했고(판정 "계획 수정 후 재검토", 지적 31개) 2판에서 고쳤습니다. 2판도 다시 검토받아(같은 판정, 지적 29개, 대부분 시험이 거짓으로 통과할 수 있는 지점) 3판에서 4.1절과 5장으로 보강했습니다. 반영 내역은 8장에 있습니다. 세 번째 계획 검토는 걸지 않습니다. 같은 문서를 검토하고 고치기를 되풀이하면 문서만 길어지기 때문입니다. 대신 구현 diff마다 /code-review와 Codex 검토를 겁니다.

G1은 7단계에서 처음으로 **실제 세대 1(PoE2) 패키지**를 만드는 완료점입니다(결정 204). 지금까지 세대 1은 세대 0 패키지 안에서 시험 목표를 주입해 흉내 냈습니다. G1은 그 흉내를 없애고, 한 커밋에서 패키지·DLL·ESP·시험을 세대 1로 바꿉니다.

- **247 시작 지급 기록**: 새 코세이브 레코드 `STRT`(판 1) = 받은 콘텐츠 ID 목록. 세대 1 저장에서는 필수 레코드이고, 없거나 손상되면 보존 모드(재지급하지 않음). CORE 끝에 필드를 붙이지 않는다(CORE v3 판독기는 뒤 바이트를 거부).
- **248 세대 1에서 꺼지는 범위**: 새로 만드는 것만 막는다. 새 전리품 생성과 공물 지급 비트, 제작 명령, 새 지도 입장·결투장·재입장, 자연 승격 추첨, 참의 발동·충전, 시작 화폐. 유지하는 것: 처치 경험치·패시브 처치 효과·보스 이정표, 보류 중인 구판 월드 드롭(WDRP)의 반환, 지도 탈출·안전 제거, 트리 할당·회수(후회의 오브, 무료 INI).
- **249 세대 1 주얼 소켓**(2026-11-26 사용자 확정): P5까지 주얼 장착을 거부하고, 이미 꽂힌 것의 회수만 허용한다(세대 1 주얼이 없고, 정리로 돌려받은 PoE1 주얼은 세대 1 어픽스 뜻이 없다). 트리의 주얼 창은 장착 버튼을 감추고 회수만 보인다. 정리가 꽂힌 주얼을 모두 돌려주므로 G1에서 기장착 주얼은 실제로 0개이고, 효과 집계도 비게 된다.
- **251 세대 0 회귀 합격 기준**: 전체 AutoTest는 82/82가 기준이다. H19는 기존 간헐 실패(원인 미확인, 2026-11-24 81/82)로 따로 세고, H19만 실패하면 그 항목을 한 번 다시 돌려 통과해야 한다. 그 밖의 새 실패·경고·미실행은 G1을 막는다. (2026-11-27 결정 264: H19 재실행 통과 없이 커밋.)

## 2. 지금 상태(2026-11-26 조사, Codex 검토로 고침)

- **있는 것**: CORE v3 쓰기·읽기와 세대 1 필수 레코드 판정(`SaveRecordFormat.cpp:511-626`), GENR 판정, 세대 GLOB 읽기(`main.cpp:80-109`)와 장부 검사기, 세대 1 트리 팩(`data/packs/gen1/tree.json`, schemaVersion 2)과 젬 카탈로그(`data/packs/gen1/gems.json`, 43종: `gem.` 24·`sup.` 19, 그중 `gem.Cyclone`은 `borrowedFrom: "poe1-3.30"`), UI의 세대 읽기(`ui/tree.js`). `stamp.py`는 메타 외에 추가 팩, ESP GLOB 형식·값, 해시·목록을 이미 검사한다. 빠진 것은 내용의 의미 검사.
- **G1을 지금 켜면 시작 단계에서 거부되는 곳**: 허용 목록이 `poe1`/0 하나(`ContentCheck.cpp:110-115`), 빈 items 팩 거부(`ItemData.cpp:87,320` → `main.cpp:129-131,174-179`), 세대 1 젬이 실제 경로에서 적재되지 않음(시험 경로 `AutoTest.cpp:3033`에서만).

- **세대 0 표를 만든 방식**(`compile_stage2.py:20,212-273`): 몸통·투구·장갑·장화 각각에서 요구 레벨 이하의 순수 방어형 최댓값을 골라 합치고, `bestResistTier`는 화염 저항 접미어 범위의 중간값. ## 4. 작업

결정 204대로 W1~W10이 한 커밋에 들어갑니다. 개발은 아래 의존 순서로 단계별로 시험하며 진행하고, 중간 단계의 빌드 통과는 "그 단계까지의 무결성"일 뿐 배포 승인이 아닙니다(`package_mod`가 부르는 `verify --release`도 개발 패키지의 무결성 검사로 씁니다).

### 4.1 2차 검토로 더한 구현 조건(3판)

번호는 2차 검토의 지적 번호입니다.

- **W4 지도(1, 18)**: 위치 기반 정리(셀 초기화 예약, 셀 안 WDRP를 회차 드롭으로 분류)는 지도 팩 검증이 성공했고(`MapPackRuntime`의 오류 없음) 그 검증된 목록에서 찾은 셀에만 쓴다. 지금은 해시 검증이 실패해도 읽은 목록이 `g_manifest`에 남고(`MapPackRuntime.cpp:173-177`), `LegacyDungeonCell`이 그 목록이나 EditorID로 셀을 찾는다(`MapDeviceRuntime.cpp:2990-3000`). 검증 실패면 저장된 스폰 ID 처리와 자격 있는 환불만 하고 셀은 건드리지 않는다. 시험: 목록이 다른 던전 B를 가리키게 어긋난 입력에서 B의 셀과 드롭이 그대로. `mapReturnPortal`(정상 귀환)도 허용 목록에 넣는다.
- **W4 보류 WDRP(2)**: "넘김"이 아니라 "실물 반환"으로 판정한다. 시체가 늦게 로드되는 경우(정리 → 저장·재로드 → 시체 로드)에도 시체 수량 증가, 바닥 잔량 0, 재로드 뒤 추적 상태를 본다. 시체 수량 증가를 확인하기 전에 바닥 물건을 지우는 경로(`WorldDropTracker.cpp:606,637`)와 안전 제거가 반환 결과를 버리는 경로(`MapDeviceRuntime.cpp:3254`)는 구현 때 확인해 고친다.
- **W4 장비(11)**: 장착 슬롯 구조체의 기본값(치명타 5%, 공격 속도 1.4, `ItemTypes.h:266-268`)과, 양손에 무기가 있을 때 더하는 공격 막기 20·쌍수 속도 ×1.10(`StatEngine.cpp:672`)은 구판 장비 기본 보너스로 보고 세대 1에서 0으로 둔다. 장착 사실로 켜지는 세대 1 패시브는 남긴다. 시험: 양손 무기·쌍수·한손+방패·맨손의 실제 스냅숏 비교.
- **W4 참(17)**: 막을 경로에 저생명 수호 발동(`CombatHooks.cpp:329`)과 이미 활성인 참의 보너스·면역(`CombatHooks.cpp:252,267`, `AilmentRuntime.cpp:536`)을 더한다.
- **W2 저항(17)**: 즉시 반영되는 세 원소 최대 저항의 90도 규칙 값으로 바꾼다. 지도의 최대 저항 하한(50)은 상한보다 크지 않게 묶는다. `DamageConversion.cpp:570`의 90은 원소 피해 감소 한도라서 바꾸지 않는다.
- **W3 모집단(10)**: PoB2 아이템 목록과 같이 `hidden`·`not_for_sale`·`demigods` 베이스를 뺀다. 정답표에 이 차이가 드러나는 행을 넣는다. 레벨 38 `bestArmour`는 숨은 베이스를 넣으면 903, 빼면 711이고, 기대값은 711이다.
- **W7 STRT 규칙(4, 5)**:
  - 세대 1 저장에는 STRT를 늘 정확히 한 개 쓴다. 받은 것이 없으면 빈 목록으로 쓰고, 두 개면 손상으로 본다.
  - ID는 P0 계약의 콘텐츠 ID 문법(ASCII 64바이트 이하)을 따른다. 지금 빌드가 모르는 유효한 ID도 지우지 않는다.
  - STRT 쓰기에 실패하면 GENR을 쓰지 않는다(기존 규칙). 무기록 최초 설치와 구판 정리의 입력에는 STRT를 요구하지 않는다.
  - INI로 지급을 끈 동안에는 빈 STRT를 쓰고, INI를 켠 로드에서 받지 않은 ready ID를 준다.
  - 부분 실패: ID마다 결과(지급·실패·설정으로 뺌)를 정리 진단에 남긴다. 실패한 ID는 다음 로드에서만 다시 주고 다음 프레임에는 다시 주지 않는다. 정리 전체를 다시 하지 않는다.
- **W7 잠금(3)**: 정상 경로의 호출자(새 게임·최초 설치·보충)는 거래(`RunSerializedTransaction`)를 열고 그 안에서 실물과 STRT를 함께 바꾼다. 정리 경로는 이미 열린 거래를 그대로 쓴다. 잠금을 쥔 경로에는 이미 확정한 세대를 인자로 넘긴다. `WorldGemGeneration()`을 `GetContentGeneration()`으로 한꺼번에 바꾸지 않는다.
- **W7 같은 틱 증거(6)**: `GrantStarter`가 끝난 직후, `Normal`로 바뀌기 전에 ID별 실물 증분과 STRT 내용, 프레임 번호를 정리 진단에 남긴다. 시험은 그 프레임이 정리 프레임과 같은지 본다. 다음 프레임 초기화에서 지급하는 구현은 실패한다.
- **W8 Spark 결제(7)**: 자동 시전에서 엔진이 계산한 청구액 0, DLL 청구 1회와 그 금액, 실측 매지카 감소, 투사체 4개와 지정 표적 피해를 각각 확인한다. 실제 입력 1회의 감소량은 따로 본다(키 입력 재현이 안 되면 사용자 관찰로 하고 미확인으로 적음). 레벨 1 Spark는 요구 능력치가 0이라 클래스 선택의 증거는 `save`가 맡는다.

  - core 젬은 생성된 카탈로그와 내용으로 대조한다(`form` 없음). 폼은 묶음↔장부↔실제 ESP로 따로 대조한다.

  - 공용 rules는 도장 전 원천의 스키마·본문을 보고, 도장 뒤에 네 팩의 조합·판을 본다.
- **W5 ESP 대조(12, 13)**: 세대 1은 패키지에 복사된 ESP를 장부·`records.json`과 대조한다. 세대 0은 얼린 ESP를 HEAD의 젬 62폼과 대조한다. 폐기 19·유지 9·신규 34의 ID별 상태·폐기 세대·FULL과, 지도·공물 17폼의 기대 ID·상태·`firstPlan`은 장부에서 다시 읽지 않고 독립된 기대표(시험 데이터)와 대조한다.
- **W1 빌드 선택(14)**: `build.bat`은 매번 `-DPOE_CONTENT_GENERATION=0|1`을 명시해서 캐시가 남지 않게 한다. 실제 문법(mods 경로 인자 포함)으로 같은 빌드 폴더에서 기본 1 → 0 → 인자 없음 1의 팩·ESP·manifest를 대조한다. 알 수 없는 인자는 배치 대상이 바뀌기 전에 실패한다.
- **W1·W2·W5 생성(16)**: 최종 `core.json`은 조립 스크립트 하나(`tools/poe2/assemble_core.py`)가 젬 카탈로그·기대 방어표·상수를 합쳐 만든다. 손으로 병합하지 않는다. 의미 지문 기준선 다섯 종류(`cls`·`asc`·`node`·`gem`·`sup`)의 기존 ID를 보존하고, 생성기 하나를 단독으로 돌려도 다른 쪽 종류는 그대로인지, 의미 변경·삭제를 거부하는지 시험한다. 구판 경로를 쓰는 Python 시험도 CTest에 넣는다.
- **배치 잔재(28)**: 실제 배치 디렉터리에서 UI 파일 해시와 `*_3_30.json`·`packs/gen1/gems.json`·manifest `staged` 항목이 남지 않았는지 본다. build ID가 틀린 명령의 거절은 따로 시험한다.

## 6. 위험과 주의

- **MO2의 세이브가 정리된다**: 개발 배치를 세대 1로 바꾸면, 그 프로필에서 PoE1 세이브를 불러올 때 확인 없이 정리된다(결정 201). 저장하지 않으면 원본은 남지만, 세대 1 배치 전에 사용자에게 알리고 배치는 허락 뒤에 한다(W9 먼저). 옛 배포 DLL은 새 GENR을 보존하지 못하므로 세대 0 패키지로 돌아갈 때 세대 1 저장을 불러오지 않는다.
- **세대 0 회귀**: G1 뒤 기본 패키지가 세대 1이므로 세대 0 회귀는 `build.bat gen0 deploy "<mods 폴더>"`로 따로 배치한다. 배치를 바꿀 때마다 사용자 허락. G1 합격 기준으로 한 번 돌린 뒤 G1 커밋을 태그로 남기고 얼린다(결정 262, P4b부터 단일 트랙).
- **잠금**: W7의 지급 함수는 정리 안에서 잠금을 다시 잡지 않는다(같은 스레드 자기 대기).
- **젬 드랍**: 드랍을 끄면 젬 드랍도 꺼진다. G1~P5에서 세대 1 젬은 시작 물건과 시험으로만 얻는다.
- **ID 고정**: 첫 공개 배포로 미뤘다(결정 261, 전에는 G1 커밋). G1~P8 개발 세이브는 1.0 반영 때 버려도 된다. 기준선 검사는 개발 중 의미 변화 감지용으로 유지.
- **`newgame` 진입**: 메인 메뉴 `coc`는 `kNewGame`을 보내지 않는다(2026-11-26 실행으로 확인). 메인 메뉴 네이티브 콜백 표의 새 게임 콜백을 부르는 방식으로 바꿈(콜백 이름은 실행 기록에 남김).
- **세대 2 이관(G1 범위 밖)**: 트리 검증기의 이관 분기(`validate_id_baseline`)는 트리 종류만 넘기고, 젬 생성기는 기준선 세대가 1이 아니면 실패한다. 세대 2를 만들 때 한 대응표가 모든 종류를 덮는지 함께 검사해야 한다.
