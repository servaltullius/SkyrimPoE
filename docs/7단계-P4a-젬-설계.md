# 7단계 P4a 젬 최소 폼·실행기 설계

2026-11-25 작성. 같은 날 Codex 교차 검토(지적 34건, "수정 후 구현")를 반영해 2판으로 고쳤다.

이 문서는 7단계(PoE2 전환)의 P4a 산출물과 그 구현 계획이다.

| 표시 | 뜻 |
| --- | --- |
| [확정] | 사용자가 고른 것 |
| [잠정] | Claude가 정했고 아직 확인받지 않은 것 |
| [미검증] | 실행해 보지 않은 것 |

- 결정 기록: `docs/설계-현황.md` 2장 결정 225~233
- 계획: `docs/7단계-PoE2-전환-계획.md` 6장의 P4a 행
- 계약: `docs/7단계-P0-계약.md` 2장(ID), 3장(팩), 4장(세이브), 5장(ESP)

## 1. 범위

**P4a가 하는 것**
1. 첫 묶음 43종(결정 229의 42종과 빌린 사이클론)마다 "획득처 → 폼 → 입력 → 비용 → 실제 효과 → 저장"을 정하고, 그것을 검사하는 완성표를 만든다.
2. 필요한 ESP 폼을 만들고 장부에 적는다(결정 231).
3. 장부에서 젬 표를 생성한다. 실물 인식, 세대별 저장 키, 장착 허용을 나눈다.
4. 실행 방식 분기와 **젬별 준비 상태**를 만든다.
5. 시험 세계에서 **한 경로를 게임에서 실행**한다. 대상은 Spark의 실제 손 시전, 그리고 구판 Chain의 실제 정리 반환과 거절이다.

**두 단계로 나눈다**

| 단계 | 내용 | 검증 |
| --- | --- | --- |
| P4a-1 | 데이터, 장부, ESP, 생성 표, 세이브 키, 준비 상태 | 단위 시험과 pytest. 세대 0 회귀는 게임 짧은 실행 |
| P4a-2 | 개발 배치의 준비 파일, 젬 시험 세계, AutoTest `-Only gems` | 게임 실행 |

**P4a가 하지 않는 것** (P4b 몫)
- Spark를 뺀 42종의 실제 동작
- 보조의 성장 방식(U-5 나머지)
- Spirit 예약 화면
- 메타 젬의 에너지 동작
- 철퇴·활 실행 방식
- 입력 선택 화면

**바꾸지 않는 것**
- 결정 204: 세대 1은 G1에서 켠다.
- 세대 0 빌드의 일반 플레이는 P4a 앞뒤로 같아야 한다.

## 2. 근거

**원천 자료**
- PoE2 0.5 원천 팩(PoB-PoE2 0.23.1): `data/poe2/raw/0.5/gems.json`, `skills.json`
- 같은 판의 PoB `Data/Gems.lua`, `Data/Skills/*.lua`

**원천 팩에서 확인한 사실** (2026-11-25 하위 에이전트 조사, 주요 항목은 Claude가 직접 다시 확인)
- 액티브 젬은 계산 행이 40개이고 자연 최대 레벨은 20이다. Tier > 0 보조는 1행이다.
- 같은 계열의 보조라도 등급마다 `grantedEffectId`가 다르다.
- Cast on Critical(`MetaCastOnCritPlayer`)
  - Spirit 100을 예약한다.
  - 에너지 획득 스탯은 `cast_on_crit_gain_X_centienergy_per_monster_power_on_crit`이다.
  - 숨은 보조 `SupportMetaCastOnCritPlayer`가 피해 −20%와, 시전 시간에 비례한 최대 에너지를 정한다.
- Cast on Elemental Ailment는 동결·감전·점화를 걸 때 충전된다.
- Herald of Ice: "Shattering an enemy with a non-Herald Attack Hit". 무기 요구 "Any Martial Weapon"에는 지팡이가 들고 완드는 없다.
- Spell Echo
  - `Cascadable`만 받는다.
  - `Triggered`·`UsedByProxy`·`Persistent`는 제외한다.
  - 메아리 때 범위가 바뀐다.
- Iron Ward의 방출은 별도 효과 `IronWardNovaPlayer`이다.
- Arctic Armour는 근접 공격에 맞으면 단계 하나를 자동으로 소비해 반격한다.
- Molten Blast는 `Attack + RangedAttack + Projectile + Area`다. `Melee`·`Strike`·`Slam`이 아니다.
- Deadly Herald는 전령에 고정 Spirit 20을 더한다.
- 레벨 1 기본(비주입) Spark: 마나 5, 번개 피해 1~10, 투사체 4개(`act_int.lua:19908,19970–19986`)

**엔진과 도구에서 확인한 사실**
- houseCARL은 FormID를 0x800부터 차례로 할당하고 지정할 수 없다. 지금 ESP는 0x8BF까지 쓴다.
- 무기 타격은 HitData 적용 훅(`CombatHooks.cpp:328`, 8개 호출 자리)을 지난다. 그 가운데 다섯 자리는 실게임 미확인이고, 화살 자리는 `nonactor_arrow`다.
- 활 발사 시점을 가로채는 수단은 없다. [미검증]

## 3. 실행 방식과 준비 상태

**실행 방식**

| 기호 | 실행 방식 | 엔진 수단 | 시점 구분 |
| --- | --- | --- | --- |
| S1 | 투사체 주문 | 칸의 대리 주문(결정 89) 손 시전 → `ProjectileRuntime` | 시전 1회 = 비용 1회, 적중마다 효과 |
| S2 | 연쇄 번개 | `ProjectileRuntime`의 연쇄 | 같음 |
| S3 | 노바 | `SkillExecution::ExecuteAoESpell` | 같음 |
| S4 | 일격 | 공격 시작에 칸과 무기를 확정하고 비용을 냄 → 일반 공격의 실적중(HitData, 예측·중복 제외)에 배율과 추가 효과를 적용. Boneshatter 충격파는 Heavy Stun 조건부 | P4b |
| S5 | 내려찍기 | 강공격 시작에 확정·비용 → 착지·적중 시 전방 광역. 여진과 Rolling Slam의 두 번째 강타는 지연 효과(주 갱신 예약) | P4b |
| S6 | 공격 투사체(Molten Blast) | 공격 시작에 확정·비용 → `ProjectileRuntime` 발사를 공격 피해로, 충돌 폭발 뒤 후방 원뿔. 근접 보조를 받지 않음 | P4b |
| S7 | 활 공격 | 발사 시점에 칸·무기 확정과 비용(가로채기 수단은 P4b 첫 작업, [미검증]) → 화살 실적중이나 지형 충돌에 적중 효과. Lightning Arrow는 S2 재사용, Ice Shot은 원뿔 파편, Poisonburst는 광역 | P4b |
| S8 | 지속 버프 | Spirit 예약(`StatEngine`). Iron Ward만 사용 입력이 있고(포효 키 대리 파워, 막은 물리 피해를 모았다가 방출) Arctic Armour는 피격 반응(근접 피격 때 자동으로 단계 소비) | P4b |
| S9 | 전령 | 처치 사건에 결정타의 출처(공격·주문·전령)와 처치 직전 상태, 초과 피해를 실음. Ice는 비전령 공격의 산산조각, Ash는 충분한 초과 피해 → 점화 폭발, Thunder는 감전된 적 처치 뒤 **후속 공격 적중**에서 번개 | P4b |
| S10 | 에너지 메타 | CoC는 치명타, CoEA는 동결·감전·점화를 걸 때 에너지를 쌓음. 발동은 결정 145대로 DLL 직접 발동(대리 주문 아님). 발동된 주문은 에너지를 만들지 않음(결정 103 깊이 1) | P4b |
| S11 | 보조 | 연결한 스킬의 계산에 적용(`SkillSystem`). 비용 단위는 배수, 고정 Spirit 가산(Deadly Herald +20) 중 원천에 있는 것 | P4b |
| S12 | 사이클론 | `CycloneRuntime`, 빌린 데이터(P7) | 있음 |

**준비 상태** [잠정]
- 젬마다 `ready` 표시를 둔다. P4a에서는 세대 1의 `gem.Spark` 하나만 `ready`다.
- 준비되지 않은 젬은 **비용·쿨다운·칸 변경보다 먼저** 장착·소켓·실행을 거절하고 이유를 보인다. 이유는 "PoE2 젬: 아직 구현 안 됨"이다.
- 실행 방식이 있다는 이유만으로 열리지 않는다. 예를 들어 S1인 Frostbolt도 P4b 전에는 거절된다.

## 4. 입력 (결정 47·232)

**한 입력에 한 칸**
- 입력 하나에는 한 칸만 켜진다.
- 기본값
  - S4 → 일반 공격
  - S5 → 강공격
  - S12 → 강공격 누르고 있기
  - S7 → 활 발사
  - 주문 → 손의 대리 주문
  - Iron Ward 사용 → 포효 키
- 그 밖(S6 Molten Blast 등)은 스킬 키다(결정 232).

**저장 계약** [잠정, 구현은 P4b]
- 세대 1 CORE에 입력별 선택 칸을 저장한다.
- 같은 입력에 새 칸을 배정하면 앞 칸의 배정이 풀린다.
- 무기가 요구를 채우지 못하면 배정은 남기고 끈다.
- 공격 스킬의 칸과 무기는 **공격 시작**(활은 발사)에 확정한다. 그 공격의 비용과 효과는 확정한 칸이 갖는다. 적중 전에 칸이나 무기를 바꿔도 바뀌지 않는다.
- 배정이 없으면 칸 번호가 낮은 쪽이 우선이다.

**무기 분류** [잠정]

| 스카이림 무기 | 채우는 PoE2 요구 |
| --- | --- |
| 한손 검·도끼·철퇴·단검 | One Hand Mace(결정 226), Any Martial Weapon |
| 양손 대검·전투 도끼·전투 망치 | Two Hand Mace(결정 226), Any Martial Weapon |
| 활 | Bow, Any Martial Weapon |
| 석궁 | Any Martial Weapon(첫 묶음에 석궁 스킬 없음, 결정 225) |
| 지팡이 | Any Martial Weapon(PoE2 `weaponTypes`에 Staff) |
| 맨손, 주문만 든 손 | 무기 무관 스킬만 |

## 5. 폼과 콘텐츠 ID [확정 231, 할당 잠정]

### 5.1 유지 판정

**규칙**: 유지 = **같은 영어 이름의 같은 스킬**. 이름이 바뀐 것과 등급으로 갈라진 것은 폐기한다. 같은 이름이라도 동작이 바뀐 것은 아래 표에 차이를 적고, 유지 여부를 판정한다.

| 세대 0 폼 | 판정 | 근거 |
| --- | --- | --- |
| Cyclone 0x814 | 유지 | 같은 데이터를 빌려 씀 |
| IceNova 0x816, Fireball 0x87D, Arc 0x87F, Spark 0x880 | 유지 | 같은 이름의 같은 주문. 주입(infusion) 같은 추가 효과만 다름 |
| HeraldOfIce 0x88D, HeraldOfAsh 0x88E | 유지 | 같은 이름의 같은 전령. 발동 조건은 공격 처치로 바뀜(결정 230) |
| SupFork 0x883 | 유지 | 같은 이름의 같은 효과(분기) |
| SupSpellEcho 0x885 | 유지 | 같은 이름. 받는 주문이 `Multicastable`에서 `Cascadable`로, 메아리가 범위 변경 방식으로 바뀜 |
| SupConcEffect 0x81C | **폐기** | 이름이 Concentrated Area로 바뀜 |
| SupMeleePhys 0x819 | **폐기** | 이름이 Heavy Swing으로 바뀜. 구판에 있던 중독·출혈 증폭이 없음 |
| 나머지 17 | 폐기 | 결정 231 |

**결과**: 유지 9, 폐기 19, 신규 34다. 실물 젬 폼은 62개이고 ESP 전체는 226폼이다.

**유지 폼의 이름**
- 유지 폼의 FULL 이름 변경(예: "보조 젬: 분기" → "보조 젬: 갈래")은 **G1에서** 폐기 폼의 "(구판)" 처리와 함께 한다.
- P4a 시험 세계의 화면 이름은 젬 팩의 한국어 이름을 쓴다.

### 5.2 콘텐츠 ID

- 묶음 파일에 **명시적인 불변값**으로 적고, 이름에서 다시 만들지 않는다. 다음 판에 등급이 늘어도 바뀌지 않는다.
- 원본 키는 따로 보관한다: `gameId`, `variantId`, `grantedEffectId`, 표시 등급, `Tier`, `gemFamily`.
- 액티브는 `gem.<이름>`, 보조는 `sup.<이름>`이다(계약 2.2). 7장 표의 값이 기준이다.
- 빌린 사이클론은 `gem.Cyclone`이고, `borrowedFrom: "poe1-3.30"`과 PoE1 원천 키(`G:\poe\PathOfBuilding-2.68.1\Data\Gems.lua`)를 둔다. P7의 "빌린 데이터 0" 검사가 이 표시를 읽는다.

### 5.3 장부 [잠정, 계약 5.1 규칙 4·7 보완]

**범위표**
- `legacy`는 0x800~0x8BF, `stage7`은 0x8C0~0xFFF다(결정 231).
- 검사기의 범위 이름과 경계, 분류 목록도 함께 바꾼다.

**준비됨(staged)**: 다음을 모두 만족하는 항목만 허용한다.
- 세대 0 기준선(`published/gen0.json`)에 없다.
- `stage7` 범위다.
- `status: active`이고 `legacyKey`가 null이다.
- `introducedGeneration`이 장부의 현재 세대 + 1이다.

**함께 검사하는 것**
- 기준선에 있는 항목의 `introducedGeneration`은 바뀌지 않는다.
- 현재 + 2 이상은 거절한다.
- `published/gen0.json`은 그대로 둔다.

**콘텐츠 ID**
- 유지 9와 신규 34에 `contentId`를 적는다.
- 검사기는 양방향 유일성, 누락, 중복, 접두(`gem.`·`sup.`), 묶음 파일과의 일치를 본다.

**구판 키**
- 장부의 `legacyKey`는 `gem:Spark` 모양이고, 세이브의 세대 0 `gemId`는 `Spark`다.
- 반환표는 접두를 뗀 값을 키로 쓴다.
- 28개 전부가 왕복하는지 시험한다.
- 검사기는 `FormIds.h`를 정규식으로 읽던 검산을 **동결 기준선**에서 하도록 바꾼다.

**세대 GLOB**
- G1에서 houseCARL이 차례로 준 번호를 장부에 적는다.
- DLL과 검사기는 0xC00 고정 대신 장부에서 생성한 번호를 쓴다. P4a는 이 번호를 받는 자리만 만든다.
- 시험할 경우: 세대 0에서 GLOB이 없을 때, 그리고 0xC00이 아닌 번호에 정상 GLOB이 있을 때.

### 5.4 의미 지문

- 43종의 의미 지문 후보를 `data/poe2/id-baseline/gen1-gems.json`으로 따로 낸다. 트리 기준선 `gen1.json`과는 섞지 않는다.
- G1에서 종류별 소유권을 정해 병합한다. 그 뒤 트리와 젬을 양쪽 순서로 재생성해 같은지 본다.

## 6. 표와 세대별 사용처 [잠정]

### 6.1 생성 표

모두 장부와 묶음 파일에서 생성한다(`plugin/src/runtime/GemFormTables.generated.h`). 손으로 고치지 않는다.

| 표 | 내용 | 쓰는 곳 |
| --- | --- | --- |
| 실물 표 | 젬 폼 62개의 FormID, 상태(세대 0 / 준비됨 / G1 폐기 예정), 세대 0 키, 세대 1 콘텐츠 ID | 실물 인식, `VerifyEspForms` |
| 세대 0 키 표 | `gemId` ↔ FormID 28개 | 세대 0 세계의 모든 소비자, 구판 정리 반환 |
| 세대 1 키 표 | 콘텐츠 ID ↔ FormID 43개와 `ready` | 세대 1 세계(시험 세계, G1 뒤) |

**`VerifyEspForms`**
- 실물 표 62개 전부의 존재, 타입, 소유 파일, 삭제 여부를 본다.
- houseCARL이 실제로 준 FormID·EditorID·이름을 읽어 장부와 대조한다.
- 신규 하나와 폐기 예정 하나가 잘못된 경우를 각각 시험한다.

### 6.2 세계와 키

- **세계의 젬 세대**: 로드할 때 정해지고, 다음 로드까지 유지된다.
  - 세대 0 세계: 지금 빌드의 일반 플레이
  - 세대 1 세계: G1 뒤, 또는 젬 시험 세계
- **실물 인식**(FormID → 실물 표 항목)은 세계와 무관한 불변 캐시다.
- **젬 ID 해석**(세이브의 문자열 → 젬 데이터)은 세계 세대마다 다른 카탈로그로 한다.
  - 세대 0 카탈로그: 지금 `core_3_30.json`의 젬
  - 세대 1 카탈로그: `gen1/gems.json`

## 8. 개발 배치의 준비 파일 [확정 233, 세부 잠정]

**준비 파일과 빌드 경로**
- 준비 파일은 정확히 `SKSE/Plugins/SkyrimPoE/packs/gen1/gems.json` 하나다. 비배포인 `gen1/tree.json`은 넣지 않는다.
- `package_mod`(일반 패키지)는 준비 파일을 넣지 않는다. 지금 동작 그대로다.
- `build.bat deploy-dev`(새 동작)는 일반 패키지를 만든 뒤 준비 파일을 복사하고, `manifest.json`의 `staged` 칸에 경로와 SHA-256을 적는다.
- `stamp.py verify`
  - 일반 파일은 지금처럼 검사한다.
  - `staged`는 따로 검사한다.
  - **릴리스 모드**에서는 `staged`가 비어 있지 않거나 준비 파일이 있으면 실패한다.
- `deploy-clean`은 manifest의 `staged` 목록에 있는 파일을 남긴다.
- 일반 `deploy`를 개발 배치 위에 다시 하면 준비 파일을 지운다.

**DLL**
- 정상 세대 0 검사(계약 3장)는 지금 그대로 한다. 준비 파일은 그 검사에 넣지 않는다.
- **젬 시험 세계를 요청할 때만** 준비 파일을 검사한다: 스키마, `game`, 세대 1, 빌드 ID 연결, manifest의 해시.
- 파일이 없거나 맞지 않으면 시험을 시작하지 않고 실패로 보고한다. 일반 플레이에는 영향이 없다.

**G1 인계**
- G1에서 `gen1/gems.json`의 내용은 세대 1 `core.json`에 들어간다. 준비 파일 경로는 G1 커밋에서 없앤다.

**완료 기준에 넣는 세 경우**
- 일반 패키지
- 개발 배치
- 개발 배치 위의 일반 재배치

## 9. 젬 시험 세계와 게임 시험 [잠정]

### 9.1 세계 수명

**로드 요청과 세계 세대를 나눈다**
- 정리 시험 목표(`SetCleanupTestTarget`)는 예상한 로드 한 번만 맞추고, 끝나면 시험 목표를 푼다.
- 젬 시험 세계는 그것과 따로 **세계 세대 = 1**을 로드부터 다음 로드까지 유지한다.
- 예상 밖의 다른 세이브를 로드하면 세대 0 세계로 돌아가고, 카탈로그와 캐시를 복원한다.

**기준 세이브**
- 무기록 기준(GENR 없음, PoE 데이터 없음): Spark 경로에 쓴다. 정리 대상이 아니다.
- 구판 기준(세대 0 데이터): Chain 반환에 쓴다. 정리 시험 목표와 함께 켠다.

**세이브 격리**
- 젬 시험 세계 동안 자동 저장 GMST를 끄고, 끝나면 되돌린다.
- 대상: `bSaveOnRest`, `bSaveOnWait`, `bSaveOnTravel`, `bSaveOnCharacterMenu` 등 [미검증: 정확한 목록]
- 그 사이 저장은 시험 슬롯(`_final`)에만 한다.
- 이번 실행에서 `_final.ess`와 `.skse`가 **둘 다** 갱신됐는지 확인한다.

**이름 충돌**
- `tools/autotest.ps1`과 DLL의 실행 표지가 `-Save`와 `_final`의 이름 충돌을 `gems`에서도 거부한다. 지금은 cleanup에만 적용된다.
- `quit=false`는 거절한다.

### 9.2 시험 순서 (AutoTest `-Only gems`)

**가. Spark 경로** (무기록 기준, 세대 1 시험 세계)
1. 시험 세계를 요청하고 준비 파일을 검사한다.
2. 유지 폼 0x880(Spark) 아이템 하나를 지급한다.
3. 칸에 장착한다. CORE에 `gem.Spark`가 저장되는지 본다.
4. **시전**한다(결정 234로 고침). 오른손 시전자의 `CheckCast`·`SpellCast(doCast=true)`를 직접 불러 우리 시전 검사 훅과 대기열 실행기를 실제와 같은 경로로 지나게 한다. 합성 버튼 입력은 엔진이 누름 유지를 받아들이지 않아(0.01초 만에 시전을 버림) 쓰지 않는다. `SpellCast` 직접 호출은 엔진의 입력 시전 과정의 매지카 차감을 지나지 않으므로, 비용은 "엔진이 청구할 비용"(`CalculateMagickaCost`)이 기대값과 같은지로 판정한다. 엔진의 실제 입력 경로와 매지카 차감은 2026-11-25 사용자 손 시전으로 확인했다.
   - 대상: 레벨 1 기본(비주입) Spark
   - 기대값: 시전 1회에 청구 비용이 마나 5의 환산값과 같고, 투사체가 **4개** 나간다.
   - 지정한 표적이 맞고, 피해가 번개 1~10을 환산한 범위 안이다. 이 판정에서는 치명타 확률을 0으로 고정하고, 표적 ES와 난이도를 기록한다.
   - 젬 요구치를 끄지 않는다. 기준 캐릭터가 요구치를 채우도록 준비한다.
5. 저장·불러오기 뒤에도 칸과 키가 그대로인지 본다.
6. 신규 미준비 폼 하나(Frostbolt)를 지급한다. 스킬 화면에 보이고, 장착이 "아직 구현 안 됨"으로 거절되며, 아이템·비용·칸이 그대로인지 본다.
7. 비용 경로의 경계: 이 시험 세계의 트리는 세대 0 트리다. 따라서 비용은 지금 결제 경로(`snap->poe2Passives`에 따른 엔진 비용)를 탄다. 세대 1 트리와 함께 도는 결제는 G1에서 검증한다.

**나. 구판 반환** (구판 기준: 부모 젬에 Chain을 끼운 세대 0 세이브, 정리와 젬 시험 세계)
1. 실제 정리 경로(`-Only cleanup`과 같은 엔진)를 돌린다.
2. 구판 0x882(Chain)가 **정확히 +1**, 신판 Chain I 폼이 **+0**인지 본다. 재로드 뒤 추가 지급이 0인지 본다.
3. 구판 Chain의 실제 소켓 요청과 구판 액티브(Shock Nova)의 실행 요청을 보낸다. 거절 사유가 나오고, 아이템이 그대로이고, 비용·효과가 0인지 본다.
4. 팔기와 버리기는 된다.

**다. 세대 0 회귀** (일반 세대 0 세계)
- 대표 젬(세대 0 Spark)의 장착·시전 거래가 지금처럼 되는지 본다.
