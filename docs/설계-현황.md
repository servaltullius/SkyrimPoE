# Skyrim PoE — 설계 현황

최종 갱신: 2026-11-12

이 문서가 프로젝트의 기준입니다. 새 세션은 이 문서부터 읽고, 결정이 생기면 같은 턴에 여기에 적습니다.
`docs/carbon-원본/`은 참고용 원문이며 아래 4장의 오류를 그대로 담고 있습니다.

## 1. 프로젝트

스카이림 SE/AE에서 Path of Exile 1의 빌드·파밍·엔드게임을 구현하는 SKSE 모드(`SkyrimPoE`)입니다.
현재 단계는 설계와 프로토타입입니다. 본 모드의 코드는 아직 없고, `prototypes/`에 시험용 코드와 모드가 있습니다(진행 상황은 6장).

경위:
- 2026-11-12 08:56~10:09 — Antigravity의 Gemini Carbon이 설계서를 v0.1에서 v2.2까지 작성.
- 2026-11-12 — Claude가 v2.2의 주장을 검증했고, Carbon의 맥락 손실 때문에 이후 작업을 Claude가 맡기로 함.

**Death Drop Overhaul의 드랍 동작** (소스 `src/Core`, GPL-3.0)
- `DropItemFromActor`는 `RemoveItem(…, kDropping, …)`으로 인벤토리에서 빼서 월드 레퍼런스로 만듦. 복제가 아님.

- API 경로에는 퀘스트 아이템 검사와 사망 여부 검사가 없음.
- 플레이어가 주웠을 때 추적이 해제되는 경로는 읽은 범위에서 찾지 못함.

**SkyUI 쪽 글 상자 재평가**
- DTF 제공자가 받는 것은 키 문자열뿐이고 아이템 정보는 오지 않음(위키의 `OnDynamicTranslationRequest(std::string_view a_key)`). 어느 개체에 대한 요청인지는 플러그인이 열린 메뉴에서 선택 항목을 직접 읽어 알아내야 함.
- 따라서 4.5의 "SkyUI 쪽 추가 비용이 작다"는 판단은 낮춰야 함. 가능은 하지만 메뉴별 선택 항목 읽기와, 키 수만큼의 구역 설계가 필요. LoreBox의 줄 수·색·키워드 부여 방식은 소스가 읽히지 않아 미확인.

**PoE 이름·데이터 사용 권리** (공개된 정책과 선례 조사. 법률 자문이 아님)
- GGG 이용약관 4조는 텍스트, 이미지, 로고와 함께 게임 내 이름·캐릭터·장소·가상 아이템까지 자사 권리로 명시. 7조 (a)는 서면 승인 없는 복제·배포·2차 저작물 작성을 금지.
- GGG 개발자 문서는 "자사 에셋을 복사해 다른 게임을 만드는 것"을 허용하지 않는 예로 들지만, 이는 상업적 수익 항목 아래에 있음. 비상업 모드를 어떻게 보는지는 문서에 없음.
- GGG가 공식 제공하는 게임 데이터는 패시브 트리 내보내기(`grindinggear/skilltree-export`)뿐이고, 그 저장소에는 라이선스가 없음.
- Path of Building의 MIT 라이선스는 소프트웨어에 대한 것이고, 저장소 어디에도 게임 데이터의 권리에 대한 언급이 없음. `src/Data`는 게임 파일(`Content.ggpk`)에서 추출해 생성한 것이라고 기여 안내에 적혀 있음. 자매 프로젝트 RePoE는 "데이터 파일은 GGG 소유"라고 라이선스에 따로 명시.
- 넥서스 규정은 권리자 허락 없는 "게임 파일이나 이미지" 포함을 금지하고, 올리는 사람이 저작권·데이터베이스권·상표권을 침해하지 않음을 보증하게 함. 다른 게임의 이름·글·수치에 대한 명문 규정은 없음.
- 선례: GGG가 팬 모드나 도구를 내리게 한 사례는 찾지 못함(비공개 요청은 알 수 없음). 오래 유지된 큰 프로젝트(Mine and Slash, Path of Terraria, Passive Skill Tree)는 시스템만 가져오고 이름을 전부 바꿨음. PoE 이름을 그대로 쓴 모드(Path of Grim Dawn 등)도 내려가지 않았지만 규모가 작음.
- 조사자의 추정 위험 순서(낮음 → 높음): 메커니즘·공식, 개별 수치, 트리 배치, 이름, 원문 그대로의 설명 글, 이미지·음향·로고.
- 근거 원문은 조사 때 받아 둔 사본이 세션 임시 폴더에 있으나 프로젝트에는 넣지 않았음.

**투사체 보조 젬의 구현 가능성** (사용자 질문, 2026-11-12)
- 엔진에 투사체를 직접 쏘는 진입점이 있음: CommonLibSSE-NG의 `Projectile::Launch(ProjectileHandle*, LaunchData&)`. `LaunchData`에 발사 원점(`origin`), 각도(`angleZ`·`angleX`), 원하는 표적(`desiredTarget`), 주문(`spell`), 크기(`scale`), 위력(`power`), 자동 조준(`autoAim`)이 들어 있음. 로컬 CommonLibSSE-NG 헤더에서 확인.
- 충돌 정보(`ImpactData`)에 맞은 대상(`collidee`)과 충돌 결과가 들어 있어, 적중 시점에 후속 동작을 붙일 수 있음.
- 선례: Fenix Projectiles API(임의 위치·방향에서 투사체 발사), Homing projectiles(유도), Archery Techniques의 다중 화살, Socketing의 "Unending"(화살이 다음 적으로 최대 10번 튐)과 "Branch"(추가 영체 화살).
- Claude 평가: 추가 투사체는 각도를 나눠 여러 번 쏘면 되어 쉬움. 관통·연쇄·분기는 적중 지점에서 새 투사체를 다시 쏘는 방식으로 구현할 수 있어 중간 난이도. 어려운 쪽은 범용성(화살, 탄환형 주문, 광선형 주문, 원뿔형 주문이 각각 다른 투사체 종류), 동시 개수 상한과 성능, 그리고 피해를 우리 전투 수식으로 일관되게 통과시키는 일. 실행으로 확인한 것은 없음.

**PoE1과 PoE2 비교** (2026-11-12 웹 조사. poewiki.net·poe2wiki.net은 봇 차단으로 열지 못해 PoE1 일부 수치는 대조하지 못함)
- 시점: PoE2는 아직 얼리 액세스(0.5.5, 2026-09-04)이고 1.0이 2026-12-11 예정. 1.0에서 보조 젬 전면 재조정, 패시브 트리 재구성, 아틀라스 트리 축소가 예고됨. PoE1은 3.30이 2026-11-13에 나오며 엔드게임이 개편됨. 우리 기준은 3.29로 고정(2장 39번).
- 젬: PoE1은 장비의 소켓과 링크에 젬을 꽂음. 3.29부터 소켓이 기본 흰색이고 젬은 색과 무관하게 장착되며 색이 맞으면 퀄리티 +10%. PoE2는 스킬 젬이 보조 소켓을 직접 가짐(기본 2개, 오브로 최대 5개 안팎). 액티브 스킬 칸 9개. "한 스킬에 같은 종류 보조 젬 1개" 제한이 있고 보조 젬에 I/II/III 등급이 있음.
- 투사체 보조(PoE2 수치): Multishot I은 투사체 +2에 피해 35% 감소, Pierce I은 1회 관통 후 피해 20% 감소, Chain I은 연쇄 +1에 피해 30% 감소, Fork는 분기 후 피해 30% 감소. PoE1의 Greater Multiple Projectiles는 투사체 +4.
- 발동: PoE1의 Cast On Critical Strike는 치명타 시 시전, 쿨다운 0.15초. PoE2는 메타 젬이 Spirit을 점유한 채 에너지를 쌓아 발동. PoE1 Cyclone은 채널링 이동 공격, 공격 속도 300%. PoE2에서는 Cyclone을 확인하지 못함.
- 지속 버프: PoE1은 마나를 비율로 점유. PoE2는 Spirit이라는 별도 고정 자원(보스 보상과 장비로 획득).
- 플라스크: PoE1은 5칸 + 자동 사용 조건 부여(Instilling Orb, 조건 15종). PoE2는 생명·마나 플라스크 + 참(Charm). 참은 벨트에 따라 1~3칸, 조건(빙결, 출혈, 기절, 화염 피격 등 13종)이 충족되면 자동 발동, 처치로 충전.
- 패시브 트리: PoE1은 포인트 123, 전직 8. PoE2도 123 + 무기 세트 패시브 24, 마스터리 선택이 없고 "+5 임의 능력치" 노드가 많음. PoE2 트리는 1.0에서 다시 짜일 예정.
- 제작: 둘 다 접두 3·접미 3. PoE2에는 Scouring, Chromatic, Fusing이 없고 장비 소켓은 룬용(몸통·양손 무기 2개, 나머지 1개).
- 전투: PoE2는 WASD 기본, 구르기, 무기 종류에 묶인 스킬.
- 엔드게임: PoE1은 지도와 지도 장치, 포털 6개. PoE2는 Waystone으로 월드맵 노드를 열고 부활 횟수가 지도 속성 수에 반비례.
- 도구 데이터: PoE1용 PoB는 2.67.2로 성숙. PoE2용 PoB는 0.23.1로 0.x 단계이고 공식 트리 내보내기에 미출시 자리표시가 섞여 있음.

Claude 평가: 내용(스킬·보조 젬·트리·전직·고유 아이템의 이름과 데이터)은 PoE1을 기준으로 삼고, 스카이림에 맞추기 쉬운 구조는 PoE2에서 빌려 오는 혼합이 맞아 보임.

- 사용자 결정이 필요한 구조 선택: 보조 젬 소켓을 장비에 둘지(PoE1) 젬 자체에 둘지(PoE2), 지속 버프를 마나 점유로 할지(PoE1) 별도 자원으로 할지(PoE2).

**설계에 주는 영향** (Claude 평가)
- 공개 배포(2장 19번)를 유지하려면 이름과 글을 어떻게 다룰지 정해야 함. 선택지: 전부 자체 이름으로 바꿈, 이름은 쓰고 설명 글은 자체 작성, 또는 엔진과 변환 도구만 배포하고 데이터는 사용자가 자기 PoB에서 직접 컴파일. 어느 쪽이든 이름·글·수치를 코드에서 분리한 데이터 팩 구조로 설계해 두면 나중에 바꿀 수 있음.
- 월드 위협도 스케일러는 유배자 레벨로 일괄 덮어쓰면 이 모드팩의 지역별 난이도 구성을 지움. 지역 레벨을 기준으로 삼는 상대 보정이어야 하고, Legendary Enemies와의 중복 승격 규칙이 필요.
- 2번째 반지·벨트는 원문의 "장착 가드 하나" 수준이 아니라 메뉴 3곳, 조건 함수, 시각 부착, 스크립트 이벤트까지 다루는 규모. 벨트는 3D가 필요 없으므로 반지보다 단순.
- UI는 뷰 하나 안에서 패시브 트리, 소켓 패널, HUD, 지도 장치 화면을 전환하는 구조가 문서 권장에 맞음. HUD와 전체 화면 패널이 한 뷰에 같이 있어야 하므로 포커스 전환 설계가 필요.
- 바닥 드랍 이름표와 루트 필터는 ARPG POV에 선례가 있음. 코드는 GPL-3.0.
- 무기를 든 채 시전하는 채널 B는 Spell Hotbar 2/NG가 같은 문제를 이미 풀었으므로 그 방식을 먼저 확인.
- DiabloRim, Socketing, Calamity처럼 아이템에 어픽스·소켓을 붙이는 모드와는 함께 쓰는 경우의 처리(감지 후 경고 또는 한쪽 양보)가 필요.

- 이 구조라면 Animation Injector 방식에서는 회전 중 이동 속도가 캐릭터의 이동 속도가 아니라 클립에 묶임. PoE의 이동 속도 옵션을 사이클론에 반영하려면 OAR 방식이 유리함(Claude의 판단, 시험 전).

- Animation Injector는 `control="rightAttack" press="hold"`로 공격 버튼의 길게 누름을 시작 조건으로 삼을 수 있고, 안내서에는 짧게 누른 입력을 게임에 돌려준다고 적혀 있음. **2차 시험에서 이 모드팩(MCO. 오늘 세션에 `MCO.dll` 로드 확인. For Honor Power Attack과 One Click Power Attack의 DLL은 로드되지 않았고, SKSE 폴더에 남은 그 로그들은 9월 이전 것임)에서는 짧은 클릭의 일반 공격이 나가지 않았음.** 소스(커밋 `dc3c0b7`)로 확인한 동작: 누름·뗌 이벤트를 `PlayerControls`로 가는 목록에서 빼 두었다가, 0.2초 안에 떼면 그다음 틱에 합성한 누름(값 1, 누른 시간 0)과 뗌(값 0, 누른 시간 0.1 고정)을 연달아 입력 관리자로 다시 보냄. 일반 공격이 안 나간 직접 원인은 미확정(합성 입력이 같은 순간에 지나가 공격 모드가 인정하지 않는다는 가설이 유력하나 증거 없음. `bDebug = true` 로그로 가를 수 있음). 원인과 무관하게, 이 방식에서는 모든 일반 공격이 버튼을 뗀 뒤 합성 입력으로 나가므로 "강공격 입력에 채널링을 얹는다"를 이 프레임워크의 입력 가로채기만으로 표현하는 것은 공개 배포용으로 권하기 어려움(Claude의 판단, 사용자 미확인). 입력을 건드리지 않는 이벤트 시작(`<Start event="…">`)은 별개이며 시험하지 않음.
- Animation Injector의 동작은 전신 상태라서 동작 중 일반 이동은 문서에 없음. 이동 키는 동작을 취소하거나(`MoveCancel`) 다른 동작으로 넘기는(`Transition on="move"`) 용도로만 설명됨. **2차 시험에서는 반복 동작 중에 이동 키로 이동이 됐음(사용자 관찰).** 안내서의 `<Rotate>` 설명(이동 키를 누르고 있으면 그 방향으로 몸을 돌림)과 클립의 전진 이동 주석이 합쳐진 결과일 수 있으나 가려내지 않음.
- OAR의 `CompareValues`는 액터 값을 비교할 수 있음(`"Value A": {"actorValue": 76, "actorValueType": "Value"}`, 76은 Variable09). 플러그인 없이 DLL이나 콘솔에서 값 하나로 조건을 켜고 끌 수 있음.
