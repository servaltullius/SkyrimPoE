# 지도 팩 복제 도구 (`tools/dungeon-clone`)

Skyrim.esm의 실내 던전 셀을 복제해 두 가지를 만든다. 지도 팩 플러그인 `SkyrimPoE_Maps.esp`(정규 ESP)와 런타임 목록 파일 `SkyrimPoE_Maps.json`이다.

- 계획: `docs/6단계-재작업-계획.md`의 R1
- 결정: 169(전용 복제 던전), 170(던전 다섯 곳, 회차·전리품 규칙)
- 바탕은 프로토타입 13(`prototypes/13-dungeon-clone`)에서 게임으로 확인한 복제 방법이다. 그 코드는 시험 기록이라 그대로 두고, 이 도구를 제품판으로 쓴다.

## 파일

| 파일 | 뜻 | 저장소 |
|---|---|---|
| `dungeons.json` | 던전 목록. 사람이 고친다. 키, 유형, 역할(map/arena), 이름, 원본 셀, 보스 앵커 지정과 그 이유, 최소 무리 앵커 수, 앵커 거리 기준 | 넣음 |
| `formid-ledger.json` | FormID 장부. 도구가 고친다. 판이 바뀌어도 같은 원본·역할에 같은 출력 번호를 준다 | 넣음 |
| `SkyrimPoE_Maps.esp` / `.json` | 산출물. 지금 위치는 `G:\skyrim-build\SkyrimPoE-maps\` | 넣지 않음 |

빌드 산출물(`bin`, `obj`)은 `Directory.Build.props`에 따라 저장소 밖 `G:\skyrim-build\SkyrimPoE-dungeon-clone\`에 생긴다.

## 명령

```
dotnet build tools/dungeon-clone/DungeonClone/DungeonClone.csproj -c Release
DungeonClone anchors     --data "<Data 폴더>" --list tools/dungeon-clone/dungeons.json
DungeonClone build       --data "<Data 폴더>" --list tools/dungeon-clone/dungeons.json --ledger tools/dungeon-clone/formid-ledger.json --out "<폴더>\SkyrimPoE_Maps.esp" [--update-ledger] [--create-ledger]
DungeonClone verify      --data "<Data 폴더>" --list tools/dungeon-clone/dungeons.json --ledger tools/dungeon-clone/formid-ledger.json --esp "<폴더>\SkyrimPoE_Maps.esp"
DungeonClone ledger-diff --old <이전 장부> --new <새 장부>
dotnet test tools/dungeon-clone/DungeonClone.Tests/DungeonClone.Tests.csproj -c Release
```

- **`anchors`**: 던전마다 원본 NPC를 보인다. 내비메쉬로 옮긴 뒤 입구까지의 거리(3차원)와, Boss 표시·시체·처음 비활성·입구 근처·옮긴 거리를 함께 보인다. 보스 앵커를 정할 때 쓴다.
- **`build`**
  - 장부에 없는 번호가 필요하면 `--update-ledger` 없이는 실패한다. 장부가 없으면 `--create-ledger`일 때만 새로 만든다.
  - 같은 장부로 두 빌드가 동시에 돌지 않게 잠근다.
  - 산출물은 임시 파일에 다 쓴 뒤, 장부를 먼저 저장하고 바꿔 넣는다.
  - 보고서(뺀 것, 뗀 스크립트, 앵커, 남긴 장치)는 표준 출력의 JSON이다.
- **`verify`**: 성공하면 마지막 줄이 `VERIFY=ok`(종료 0)이다. 검사에 실패하면 `VERIFY=fail`(종료 6)이다. 입력 자체가 규칙에 어긋나면(깨진 장부, 모르는 필드 등) 요약 없이 종료 7로 끝난다.
- **`ledger-diff`**: 이전 장부에 있던 구간·키·번호가 모두 그대로인지 본다. 장부를 고쳐 커밋하기 전에 `git show HEAD:tools/dungeon-clone/formid-ledger.json`으로 꺼낸 이전 장부와 비교한다. 장부 하나만으로는 되돌림·맞바꿈을 알 수 없어서다.
- **종료 코드**
  - 2: 인자 오류(모르는 인자, 두 번 준 인자 포함)
  - 3: 파일 없음
  - 6: 검사 실패
  - 7: 입력·규칙 위반
  - 8: 장부 갱신 필요
  - 9: 파일 입출력 오류

## 복제 규칙

원본은 Skyrim.esm 판만 쓴다. 다른 모드의 셀 수정은 들어가지 않는다(결정 40, 170). 마스터는 Skyrim.esm 하나다. 빼는 것과 떼는 것은 번호를 주기 전에 원본 기준으로 정한다(`Builder.Plan`).

1. **빼는 것**: 뺀 참조를 가리키던 연결은 빈 연결이 되고, 보고서에 남는다(NPC로 가던 연결 포함).
   - 배치 NPC 전부
   - 바닥 물건: 무기, 방어구, 물약·음식, 재료, 잡화, 책, 화살, 영혼석, 두루마리, 레벨드 아이템
   - 열쇠, 상자
   - 들고 갈 수 있는 광원
   - 채집 식물(수확물이 있는 Flora)과 채집 나무(수확물이 있는 Tree, 예: 매달린 이끼)
   - 광맥과 곡괭이 자리(`MineOreScript`, `MineOreFurnitureScript`)
   - 기본 객체 스크립트가 허용 범위를 넘는 대상을 가리키는 참조. 예: 동료 대사 트리거, 무기 거치대(바닐라 전역에 씀), 단어 벽 트리거, 고분 전용 퀘스트 트리거, 장작 받침대
   - **퀘스트 트리거**: 참조의 위험 스크립트를 떼어도 같은 이름의 스크립트가 기본 객체에 남는 참조. 빈 속성으로 다시 돌므로 참조째 뺀다. 예: `defaultSetStageTRIG` 계열
2. **스크립트**
   - 스크립트 속성이 가리키는 대상을 위험 종류로 나눈다.
     - 금지: 퀘스트, 위치, 조우 구역, 복제본 밖의 참조·셀·월드스페이스·내비메쉬, 찾을 수 없는 대상
     - 키워드, 전역 변수, 팩션
   - 허용 목록(`Policy.AllowedDeviceScripts`)의 스크립트는 그 스크립트에 허용한 종류만 남길 수 있다. 근거는 CK `Scripts.zip`의 원본이다.

     | 스크립트 | 허용 대상 | 근거 |
     |---|---|---|
     | `TrapTriggerBase` 계열(`PressurePlate`, `TrapFirePlate`, `TrapLever`, `TrapTriggerTimeInterval`, `TrapOilPool`) | 키워드·전역·팩션 | 소유 팩션과 LightFoot·LightHands 전역을 읽기만 함 |
     | `doorBar`, `default2StateActivator` | 키워드 | |
     | `defaultActivateSelf` | 팩션 | 읽기만 함 |

   - 그 밖의 스크립트는 위험 대상이 하나라도 있으면 뗀다. 뺀 참조를 가리키는 스크립트도 뗀다. 허용 목록 스크립트가 뺀 참조를 가리키면 보고만 한다.
3. **결정 171: 결정 170 U-5의 예외**(2026-11-22 사용자 확정)
   - 횃불 촛대(`RemovableTorchSconce01SCRIPT`)는 남긴다. 던전 조명의 상당 부분이라서다.
   - 이 촛대에서 횃불(`Torch01`)을 얻을 수 있다. 빼면 셀이 어두워진다.
   - Embershard에 22개가 있다. 보고서의 `keptItemGivers`에 나온다.
4. **문**
   - 셀 밖으로 가는 순간이동을 지운다. 목적지는 원본에서 배치 참조로 찾아야 하고, 못 찾으면 실패한다(DLC 등 다른 플러그인으로 가는 문 포함).
   - 지운 문은 세 가지로 나눠 목록 파일에 적는다.
     - 자동 문(`Door.Flag.Automatic`): 자동 출구. 원래 목적지(`exterior`/`interior`), 위치, 회전을 함께 적는다.
     - 직접 여는 문이고 원래 목적지가 야외: 귀환 문
     - 직접 여는 문이고 원래 목적지가 다른 실내 칸: 막힌 문. 순간이동만 없앤 것이고, 물리적으로 막은 것은 아니다.
   - 순간이동을 지우지 않은 안쪽 문은 잠금을 푼다.
5. **입구 마커**: `COCMarkerHeading`이 정확히 하나여야 한다. 영구 참조로 옮긴다.
6. **스폰 앵커**
   - 시체가 아닌 원본 NPC 자리에 영구 `XMarkerHeading`을 둔다. 처음 비활성인 NPC의 자리도 좌표만 쓴다.
   - 그 자리가 걸을 수 있는 내비메쉬 위가 아니면, 걸을 수 있는 삼각형 위의 가장 가까운 점으로 옮긴다.
     - "위"의 판정: 2D로 삼각형 안이고, 면과의 높이 차가 48유닛 이하
     - 걸을 수 있는 삼각형: 삭제·물 표시가 없고 넓이가 있는 삼각형
     - 관이나 파이프 속 매복 자리에 갇히지 않게 하려는 것이다.
   - 버리는 앵커
     - 옮긴 거리가 `anchorMaxSnapDistance`(256)를 넘는 것
     - 입구에서 `anchorMinDistanceFromEntry`(600) 안인 것
     - 이미 고른 앵커와 `anchorMinSeparation`(128)보다 가까운 것
   - 보스 앵커
     - Boss 표시(위치 참조 유형 `000130F7`)가 하나뿐이면 그것을 쓴다.
     - 없거나 여럿이면 목록의 `bossAnchor`(와 그 이유)로 정한다.
     - 보스가 위 조건에 걸리거나, 무리 앵커가 최소 개수보다 적으면 실패한다.
   - 걸을 수 있는 내비메쉬 위라는 것은 입구에서 걸어서 닿을 수 있다는 뜻이 아니다. 실제 경로는 게임에서 확인할 것이다(실험 E).
7. **셀**
   - 위치, 조우 구역, 소유자를 비운다.
   - EditorID는 `SPOE_Map_<key>`, 이름은 목록의 한글 이름이다.
   - 자식 EditorID에는 `SPOE_Map_<key>_` 접두사를 붙인다.
8. **문자열**: 코어 ESP처럼 UTF-8로 쓰고 읽는다. Mutagen 기본값(서유럽 코드 페이지)으로 쓰면 한글 이름이 깨지는 것을 검증기가 잡았다. 게임 표시는 미확인이다.

## FormID 장부

- 던전마다 `0x2000`칸 구간을 하나 준다. 구간은 처음 나온 순서대로 뒤에 붙고, 목록에서 던전 순서를 바꿔도 그대로다.
- 구간은 원본 셀(`Skyrim.esm:0B6BE6` 등)에 묶인다. 같은 키에 다른 원본을 주거나 같은 원본에 다른 키를 주면, 갱신을 허락해도 실패한다.
- 키는 `원본 플러그인:원본 로컬 번호:역할`이다. 역할은 `cell`, `ref`, `anchor` 가운데 하나다.
- 한 번 준 번호는 지우지 않는다. 그래서 `[base, next)`의 번호가 빈틈없이 쓰여 있어야 한다(밀도 검사).
  - 어떤 참조가 빠져도 그 번호는 다른 참조에 다시 쓰이지 않는다.
  - 남은 참조의 번호는 그대로다.
- 장부를 옛 사본으로 되돌리거나 값을 맞바꾼 것은 `ledger-diff`로 잡는다.

## 검증(`verify`)이 보는 것

1. **재현**
   - 같은 목록·장부·Skyrim.esm으로 메모리에서 다시 만든 결과와 디스크 ESP를 레코드마다 깊은 비교한다(Mutagen `Equals`, 자식 순서 포함). 목록 파일도 다시 만든 것과 같아야 한다.
   - 디스크 파일이 "만든 대로"인지 보는 검사다. 만드는 코드의 논리 오류는 아래 원본 대조가 맡는다.
2. **원본 대조**: 장부로 출력 레코드를 원본 레코드에 짝지어, 만드는 코드와 따로 확인한다.
   - **참조**
     - 기본 객체, 위치·회전, 크기, 레코드 플래그(입구 마커의 영구 플래그만 예외)
     - 연결 필드: 활성화 부모, 연결 참조, 활성화 부모 목록. 원본 연결을 장부로 옮긴 값과 필드별로 같아야 한다.
     - 셀 안 순간이동과 끊은 순간이동
     - 잠금: 안쪽 문은 풀림, 그 밖은 원본 그대로
     - 스크립트: 원본의 부분집합이고, 뗀 것마다 근거가 있어야 한다. 남은 스크립트의 연결 속성은 원본을 옮긴 값이어야 한다.
   - **내비메쉬**: 부모 셀, 꼭짓점, 격자, 삼각형(꼭짓점·이웃·플래그), 문 삼각형, 가장자리 연결
   - **뺀 원본 자식**: 사유가 있어야 한다. 형식 사유는 검증기가 따로 판정하고, 스크립트 사유는 복제 계획과 맞춰 본다. 반대로 형식상 빼야 하는 참조가 남으면 실패한다.
   - **앵커**: 원본이 시체가 아닌 NPC이고, 원본 자리에서 상한 거리 안이며, 회전이 원본과 같아야 한다.
   - **문 목록**: 원본에서 끊어야 하는 문과 정확히 같아야 하고, 분류가 맞아야 한다.
3. **불변식**: 디스크만 보고 확인한다.
   - 헤더: 마스터는 Skyrim.esm 하나, ESL 아님, HEDR 1.71
   - 레코드 구성: 셀과 그 자식만 있음. 번호 겹침, 다른 플러그인 번호, NPC, EditorID 겹침이 없음
   - 블록·하위 블록의 번호와 그룹 형식, 빈 블록·겹친 블록 없음
   - 셀: 위치·조우 구역·소유자 비었음, 내비메쉬 있음, 이름이 목록과 같음
   - 모든 번호가 그 던전의 장부 구간에 있음
   - 입구 마커
   - 앵커: 번호·이름(`_Boss`, `_Pack01`부터 차례로)·영구 여부·입구 거리·내비메쉬 위·서로 간격
   - 문 목록의 문이 순간이동 없는 문임. 남은 순간이동은 같은 셀의 문으로만 감
   - 남은 스크립트가 허용 범위 안이고, 안쪽 문이 잠기지 않음
   - 바깥 연결: 다른 던전이나 바닐라 월드 상태를 가리키지 않음. 허용 목록 스크립트는 그 스크립트에 허용한 종류만 예외로 둔다.
   - 목록 파일: 필수 필드가 있고, 모르는 필드가 없고, 형식 판이 맞고, ESP 해시가 일치함
4. **보지 않는 것**(게임에서 확인할 것, 실험 단계 E)
   - 경로 찾기와 NAVI 필요 여부, 입구에서 앵커까지 걸어서 닿는지
   - 룸바운드 가림
   - 스크립트의 실제 동작
   - 자동 출구 너머 빈 공간
   - 한글 셀 이름 표시

## 시험(`DungeonClone.Tests`)

18개 시험이 있고, 모두 게임 데이터가 필요 없다.
- **장부 단위 시험 9개**
  - 추가, 삭제, 순서 바꿈, 새 던전
  - 원본 결합
  - 갱신 없는 새 번호, 구간 초과
  - 깨진 장부: 겹침, 지운 키, 구간 틈, 같은 원본 두 구간
  - `ledger-diff`의 맞바꿈·되돌림
- **통합 시험 9개**: 메모리에 만든 작은 원본(이름 Skyrim.esm)을 쓴다.
  - 두 판 번호 보존: 원본에서 참조 하나를 빼고 하나를 더해도 남은 참조·앵커의 번호가 그대로이고, 빠진 번호는 다시 쓰이지 않는다.
