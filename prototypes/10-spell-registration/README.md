## 첫 시험 결과 (2026-11-18)

게임 한 판(10:01~12:02)의 로그 `PoEProtoSpells.log`(259줄)와 사용자 확인으로 판정함. 설치는 가로채기 3/3, 대리 레코드 8/8. `SpellCast`(0x09)와 `CheckCast`(0x0A)는 Dynamic Magic Modification Framework(`DynamicMagicModificationFramework.dll`)가 먼저 가로채고 있었고 그 위에 겹쳐 설치함. 겹친 탓으로 보이는 이상은 없었음.

**물음 1. 바꾸기: 됨(비용·투사체·이름).** F6으로 A→B를 바꾼 뒤 칸 3(보조 화염 화살 30 → 얼음 가시 35)의 첫 시전(12:00:31)에서 엔진 비용이 31.114(=35×0.889, 아래 물음 4)이고 쿨다운 3초가 걸림. 투사체가 바뀐 것은 사용자가 확인함. 바꿀 때 손에 장착한 채였는지는 따로 적지 못함. 시전 시간(차지)의 변화는 판정하지 못함.

**물음 2. 화면 반영: 마법 메뉴는 됨, 나머지 미확인.** 마법 메뉴의 이름이 바뀐 것은 사용자가 확인함. 손 HUD, 즐겨찾기, Wheeler, Casting Bar는 확인하지 못함.

**물음 3. 공통 자리: 손과 파워는 `CheckCast`와 `SpellCast`를 지남. 이중 시전과 콘솔은 시험되지 않음.**
- 오른손(시전 원천 1), 왼손(0), 파워(2) 모두 `CheckCast` → `SpellCast` 순서로 지남. `CastSpellImmediate`는 한 판 내내 한 번도 불리지 않음.
- 손 시전 한 번에 `CheckCast`가 2~3번(차지를 시작할 때부터 놓기 직전까지), `SpellCast`가 놓을 때 한 번 불림. 파워는 `CheckCast` 한 번 뒤 `SpellCast`.
- `CheckCast`는 시전과 무관하게도 불림: 대리 넷을 한꺼번에, 시전 원천 0~3마다 판정하는 묶음이 17번 있었음(진행 중인 시전 비용 없음). 화면이 "시전할 수 있는가"를 묻는 것으로 보이며 어느 메뉴인지는 미확인. 그래서 `CheckCast`의 거부는 실제 시전 시도와 화면의 질의를 가리지 못함.
- `CheckCast`와 `SpellCast`는 여러 스레드(스레드 ID 7가지)에서 불림.
- 이중 시전: 사용자는 해 봤지만 로그의 이중 시전 열은 모두 false. 로그에 있는 "두 손 동시 시전"은 서로 다른 대리 주문이었음(배정 A의 칸 1·3, 배정 B의 칸 1·2. 모두 이름이 "화염 화살"). 이중 시전은 같은 주문을 두 손에 들어야 하므로 시험되지 않은 것으로 봄.
- 콘솔 `cast`는 하지 않음.

**물음 4. 비용·쿨다운**
- (가) 쿨다운의 거부: 됨(로그 기준). 배정 A의 칸 2(얼음 가시, 3초)를 쏜 1초 뒤의 시도가 `CheckCast`에서 거부되고(원래 결과 true → false, 사유 0 → 2, 남은 2.014초) 알림이 뜸. 뒤에 `SpellCast`가 없어 시전은 일어나지 않음. 파워는 8초 쿨다운 동안의 시도가 두 차례에 걸쳐 모두 거부되고, 8.5초 뒤의 시도는 통과함. 다만 사용자는 "쿨다운이 없다"고 느낌. 사용자가 주로 쏜 "화염 화살"은 쿨다운 0초인 칸 1과 쿨다운 있는 칸(A의 칸 3, B의 칸 2)이 같은 이름이라 구별되지 않았고, 손 주문이 막힌 것은 로그에 한 번뿐임. 거부된 시도에서 매지카가 줄지 않았는지는 미확인.
- 파워를 쓴 직후 약 3초 동안은 엔진이 먼저 거부함(원래 결과 false, 사유 0). 그때도 우리 쿨다운 알림이 뜸.
- (나) 엔진 비용은 `costOverride` × 0.889. 20 → 17.779, 30 → 26.669, 35 → 31.114로 칸·배정과 상관없이 같은 배율. `ManualCostCalc`여도 엔진이 깎음. 0.889의 출처(기술 수치, 퍽, 장비)는 미확인.
- 매지카는 `SpellCast` 안에서 줄지 않음: 18번 모두 부르기 전과 뒤의 값이 같음. 회복이 멈춘 사이의 연속 시전(칸 1)에서 시전과 시전 사이에 17.779, 17.728이 줄어 엔진 비용과 1 안에서 같음. 그러니 매지카는 `SpellCast`보다 앞에서 빠짐(차지 중에 빠지는 것으로 보임, 미확인). 검수 때 Ghidra로 읽은 "SpellCast가 매지카를 뺌"과 다름.
- 매지카가 비용보다 적을 때 엔진이 스스로 거부함(사유 1 `kMagicka`, 12:01:46~12:02:00). 엔진의 매지카 판정이 우리가 정한 비용을 따름.
- (다) 이중 시전 배수: 시험되지 않음.

**물음 5. 저장 왕복: 시험되지 않음.** 12:02에 불러온 것은 대리 주문을 배우기 전의 원래 세이브였음(사용자 확인). 그래서 세 번의 불러오기 모두 `HasSpell`이 false. 대신 확인된 것: 같은 게임 한 판 안에서는 불러오기를 해도 대리 레코드의 값이 ESP 값으로 돌아가지 않고 마지막으로 적용한 배정의 값이 남음(10:59와 12:02의 `LOADSTATE`). 그러니 불러올 때마다 다시 적용하는 것은 세이브가 값을 남기는지와 상관없이 필요함(안 하면 앞 캐릭터의 구성이 다른 세이브로 넘어감). 세이브가 값을 남기는지는 게임을 끄고 다시 켠 뒤 불러와야 가릴 수 있음.

**물음 6. 같은 젬 둘: 비용은 칸마다 따로 됨, 쿨다운의 따로 거부는 보지 못함.** 배정 B에서 이름이 같은 칸 1과 칸 2를 두 손에서 함께 쏨(12:01:18): 엔진 비용 17.779와 26.669, 쿨다운 0초와 2초가 칸마다 따로 걸림. 한쪽이 쿨다운으로 막히고 다른 쪽이 나가는 장면은 로그에 없음. 화면에서는 두 주문이 이름이 같아 사용자가 어느 칸인지 가리지 못했음.

**다음 시험에서 볼 것**
1. 저장 왕복: 대리 주문을 배우고 배정 B로 바꾼 뒤 저장 → 게임을 완전히 끄고 다시 켬 → 그 세이브를 불러옴. `LOADSTATE`의 값(ESP 값인지 B의 값인지)과 `HasSpell`, 즐겨찾기 등록을 봄.
2. 이중 시전: 같은 대리 주문 하나를 두 손에 장착(파괴 이중 시전 퍽 필요)하고 함께 시전.
3. 콘솔 `player.cast <폼 ID> <대상>`.
4. 쿨다운이 있는 칸(배정 A의 칸 2 얼음 가시)만 손에 들고 쏜 직후 다시 시도하며 매지카 막대를 봄.
5. 손 HUD, 즐겨찾기, Wheeler의 이름.

통합 설계서 14장의 4번("주문 등록")에 해당합니다. 폴더 번호가 10인 것은 만든 순서입니다. 저장소의 서브모듈 `external/CommonLibSSE-NG`(v16.4.0, 결정 60)로 빌드합니다.

## 무엇을 확인하는가

주문 스킬은 실제 주문으로, 즉발 스킬은 파워로 내보내 손에 장착하거나 포효 키로 씁니다(결정 47). 젬과 그 주문은 스킬 칸마다 미리 둔 고정 대리 주문으로 잇고, 칸에 든 젬이 대리 주문의 이름·효과·비용을 정합니다(결정 89). 스킬 칸은 9개입니다(결정 88). 이 프로토타입은 이 방식이 엔진과 화면 도구에서 실제로 되는지를 봅니다.

1. **대리 주문을 실행 중에 바꿀 수 있는가.** 이름, 비용, 시전 시간, 효과의 크기, 효과 설정의 투사체를 바꾸면 다음 시전부터 그대로 나가는가. 손에 장착한 채로 바꿔도 되는가.
2. **바꾼 것이 화면 도구에 보이는가.** 마법 메뉴, 즐겨찾기 메뉴와 단축키, Wheeler, 손의 주문 이름(HUD), Casting Bar.
3. **모든 시전 경로가 지나는 공통 자리가 있는가.** 손 시전(한 손, 두 손에 다른 주문, 이중 시전), 파워(포효 키), 즐겨찾기 단축키, Wheeler, 콘솔 `cast`가 엔진의 `MagicCaster` 가상 함수 `CheckCast`(0x0A), `SpellCast`(0x09), `CastSpellImmediate`(0x01) 가운데 어디를 지나는지.
4. **비용과 쿨다운을 우리가 정할 수 있는가.** `CheckCast`에서 거부하면 시전이 막히고 매지카가 들지 않는가. 엔진이 빼는 매지카가 우리가 정한 비용과 같은가. 이중 시전의 배수.
5. **저장 왕복.** 바꾼 이름·비용·효과, 플레이어가 대리 주문을 아는 상태, 즐겨찾기 등록이 저장하고 불러온 뒤에 어떻게 되는가. 다시 적용해야 하는지.
6. **같은 젬 둘.** 두 칸에 같은 젬(이름은 같고 보조만 다름)을 넣으면 두 대리 주문이 각자의 비용·쿨다운으로 따로 동작하는가(14장 12번의 젬 쪽).

보지 않는 것: 피해(시전하면 보이는 투사체만 나가고 피해 효과는 없음. DLL이 피해를 주는 길은 프로토타입 6에서 봄, 결정 55), 보조 젬의 효과, 공격 입력에 스킬 얹기(프로토타입 2), Spell Hotbar NG(이 모드 목록에 없음. 직접 시전하는 외부 도구의 길은 콘솔 `cast`로 대신 봄. 나중에 깔면 같은 플러그인으로 따로 봄), Grid Inventory의 퀵 휠(없음), 9칸 전체 규모의 목록 표시.

## 무엇을 만드는가

**ESP `PoEProtoSpells.esp`(ESL 표시, houseCARL로 만듦)**
- 대리 주문 셋(`PoEProto10_Slot1`~`Slot3`): 주문 종류 Spell, 어느 손이든, 조준(Aimed), 쏘는 주문. 비용은 `costOverride`로 고정 표시.
- 대리 파워 하나(`PoEProto10_Power1`): 주문 종류 Power(포효 키), 자기 자신(Self).
- 칸마다 효과 설정 하나씩(`PoEProto10_Slot1Effect`~`Slot3Effect`, `Power1Effect`): 피해가 없는 Script 원형, 크기 0. 주문 칸의 효과 설정은 바닐라 투사체(화염 화살·얼음 가시 등. 만들 때 houseCARL로 폼 ID를 대조)를 가짐. 칸마다 효과 설정을 따로 두는 것은 칸마다 다른 투사체를 실행 중에 바꾸기 위해서임(한 효과 설정을 여러 칸이 나누면 서로 덮어씀).

**플러그인 `PoEProtoSpells.dll`**
- 데이터를 불러온 뒤 대리 레코드를 ESP와 로컬 폼 ID로 찾음(실행 중에는 에디터 ID를 쓸 수 없음).
- 새 게임과 불러오기 뒤 플레이어가 대리 주문·파워를 모르면 가르치고, 지금의 구성을 대리 레코드에 적용함.
- 구성(INI): 젬 몇 개(이름, 비용, 시전 시간, 쿨다운, 투사체)와 칸 배정 둘(A, B). **F6**으로 A와 B를 바꿈. 장착한 채로 바꿔도 되는지(물음 1·2) 보려는 것.
- `PlayerCharacter`의 `MagicCaster`(손 둘과 목소리) 가상 함수 `CheckCast`, `SpellCast`, `CastSpellImmediate`를 가로채, 대리 주문이 지나갈 때마다 로그에 적음(경로, 손, 이중 시전, 그때의 매지카, 엔진이 계산한 비용). 원래 함수는 늘 정확히 한 번 부름(거부할 때만 빼고, 아래).
- 쿨다운: 칸마다 쿨다운이 남아 있으면 `CheckCast`에서 거부하고 화면에 알림. 쿨다운은 시전이 실제로 일어난 때(`SpellCast`)부터 셈. 이 거부가 모든 경로에서 듣는지가 물음 4.
- **F7**: 지금 구성과 칸마다 남은 쿨다운, 대리 레코드의 현재 이름·비용을 화면과 로그에 냄.
- 대리 주문이 아닌 주문은 건드리지 않음.

## 실행 전에 남은 위험

- 대리 주문의 이름을 바꾸는 것(`TESFullName`)이 메뉴에 바로 보이는지, 메뉴가 이름을 캐시하는지 모름.
- 엔진이 기본 폼(SPEL·MGEF)을 실행 중에 바꾼 것을 세이브에 남기는지 모름. 남기지 않으면 불러올 때마다 다시 적용해야 하고, 남기면 ESP를 고친 뒤에도 예전 값이 남을 수 있음(물음 5).
- 파워가 `MagicCaster`의 같은 가상 함수를 지나는지, 콘솔 `cast`가 `CastSpellImmediate`를 지나는지는 헤더로만 읽은 것임.
- `CastSpellImmediate`는 비용 없이 시전하는 길로 읽힘. 그 길에서는 쿨다운만 막을 수 있고 비용은 우리가 직접 빼야 할 수 있음.
- 이 모드 목록에 마법 시전을 바꾸는 모드가 있음: Dynamic Magic Modification Framework(주문을 실행 중에 바꿈), Magic Casting Utilities(`MagicUtil.dll`), Dual Casting Fix(`po3_DualCastingFix.dll`), Casting Bar. 우리 대리 레코드나 가로채기와 겹칠 수 있으니, 이상하면 하나씩 끄고 다시 봄.
- 새 ESP가 MO2에 생기므로 사용자가 MO2에서 켜야 함(MO2가 켜져 있는 동안 `modlist.txt`를 직접 고치지 않음).

## 플러그인이 하는 일

데이터 로드 때 `PoEProtoSpells.esp`의 SPEL 4개와 MGEF 4개를 로컬 폼 ID로 찾습니다. 모두 찾으면 `ActorMagicCaster`의 기본 vtable에 `CastSpellImmediate`(0x01), `SpellCast`(0x09), `CheckCast`(0x0A)를 설치합니다. 슬롯이 다른 DLL을 가리키면 그 DLL 이름을 적고 기존 함수를 이어 부릅니다. 로그에 게임 런타임과 찾은 레코드 수, 설치한 슬롯 수를 적습니다. 레코드가 빠졌으면 불러온 뒤 화면에 알립니다.

새 게임과 성공한 불러오기 직후에는 메인 스레드에서 쿨다운을 비우고 현재 폼 값과 플레이어가 아는 주문을 기록합니다. 이어서 모르는 주문을 가르치고 `StartPreset`의 배정을 적용합니다. 파워 칸은 동봉 ESP의 LesserPower로 포효 키에 장착합니다.

`Data/SKSE/Plugins/PoEProtoSpells.ini`의 `[Gem.<이름>]`에 표시 이름, 정수 비용, 시전 시간과 쿨다운(초), 선택할 투사체(`Plugin.esp|0x로컬폼ID`)를 지정합니다. `[PresetA]`와 `[PresetB]`에서 각 칸에 젬을 배정합니다. 적용할 때 주문의 이름·수동 비용·시전 시간을 바꾸고, 투사체를 지정한 젬은 그 칸 MGEF의 투사체도 바꿉니다. 잘못된 젬이나 투사체가 있으면 그 칸의 적용을 건너뛰고 알립니다.

| 칸 | SPEL / MGEF 로컬 ID | 배정 A (이름, 비용 / 쿨다운) | 배정 B (이름, 비용 / 쿨다운) |
| --- | --- | --- | --- |
| Slot1 | `804` / `800` | `Firebolt` 화염 화살, 20 / 0초 | `Firebolt` 화염 화살, 20 / 0초 |
| Slot2 | `805` / `801` | `IceSpike` 얼음 가시, 35 / 3초 | `FireboltSupport` 화염 화살, 30 / 2초 |
| Slot3 | `806` / `802` | `FireboltSupport` 화염 화살, 30 / 2초 | `IceSpike` 얼음 가시, 35 / 3초 |
| Power1 | `807` / `803` | `Power` 시험 파워, 0 / 8초 | `Power` 시험 파워, 0 / 8초 |

플레이어의 대리 주문만 쿨다운을 적용합니다. `LogAllPlayerSpells=true`로 바꾸면 대리 레코드 밖의 주문도 로그에서 볼 수 있습니다. `CheckCast`는 엔진의 판정을 먼저 읽습니다. 그 판정이 성공이고 쿨다운이 남았으면 시전을 거부하고 `CooldownReason`을 반환합니다. 기본값 2는 CommonLib의 `MagicSystem::CannotCastReason::kPowerUsed`이고, 매지카 부족은 `kMagicka = 1`입니다. 엔진이 이미 거부한 시도는 그 판정과 사유를 유지합니다. `SpellCast`가 `doCast=true`로 끝나거나 `CastSpellImmediate`를 통과하면 칸의 쿨다운이 시작됩니다. 쿨다운 중에 `CastSpellImmediate`가 직접 불리면 기존 함수를 건너뜁니다. 매지카는 엔진에 맡기고 두 함수의 호출 전후 값을 기록합니다.

`PresetKey`(기본 F6, `0x40`)로 A와 B를 바꾸고 `StateKey`(기본 F7, `0x41`)로 각 칸의 젬, 폼 값, 남은 쿨다운을 봅니다. 키는 메뉴와 콘솔을 닫은 상태에서 동작합니다. 배정을 바꿔도 진행 중인 쿨다운은 칸에 남습니다. `Notify`는 불러오기·배정 전환 안내의 표시를 정합니다. 설정 오류, 쿨다운 거부, F7 상태는 표시합니다.

## 로그의 형식

SKSE 로그 폴더의 `PoEProtoSpells.log`에서 태그로 줄을 찾습니다. 로그 앞의 날짜·시각과 수준 뒤에 태그, 플러그인 로드 후 경과 마이크로초, 스레드 ID, 아래 열이 탭으로 이어집니다. 폼 ID는 런타임 값의 8자리 16진수입니다. 값이 없거나 해당 경로에 적용되지 않는 칸은 `-`입니다.

| 태그 | 스레드 ID 뒤의 열 순서 |
| --- | --- |
| `CAST` | 경로(`check` / `spellcast` / `immediate`), 시전 원천, 이중 시전, 주문 폼 ID, 칸, 원래 결과, 최종 결과, 원래 거부 사유, 최종 거부 사유, `doCast`, 즉시 시전 차단 여부, 앞 매지카, 뒤 매지카, `currentSpellCost`, `costOverride`, 남은 쿨다운(초) |
| `APPLY` | 배정, 칸, 주문 폼 ID, 젬 ID, 적용 전 폼 값 5열, 적용 뒤 폼 값 5열, 설정 쿨다운(초) |
| `LOADSTATE` | 칸, 주문 폼 ID, 적용 전 `HasSpell`, 적용 전 폼 값 5열 |
| `STATE` | 배정, 칸, 주문 폼 ID, 적용된 젬 ID, 현재 폼 값 5열, 남은 쿨다운(초) |
| `MODE` | 이전 배정, 새 배정 |
| `LAUNCH` | 호출 자리, 칸, 주문 폼 ID, 발사자 참조 폼 ID, 플레이어 여부, `castingSource`, `inFire`, `inImmediate`, 허가 여부, 투사체 참조 폼 ID, 투사체 기본 폼 ID, `power` |
| `PHIT` | 투사체 참조 폼 ID, 칸, 등록부 판정, 발사 뒤 경과(초), 맞은 참조 폼 ID, `castingSource` |

폼 값 5열은 표시 이름, 비용, 수동 비용 플래그, 시전 시간(초), 투사체 폼 ID 순서입니다. `CAST`의 시전 원천은 `GetCastingSource` 값(0 왼손, 1 오른손, 2 기타, 3 즉시, 4 없음)입니다. `check`는 판정 직후 비용을 읽고 매지카 두 열은 비워 둡니다(`-`). 두 실행 경로는 원래 함수를 부르기 전에 비용을 읽고, 허용된 시전은 쿨다운 시작 직후의 남은 시간을 적습니다. 차단된 `immediate`는 기존 함수를 부르지 않은 상태에서 앞뒤 매지카를 읽습니다.

## 시험하는 법

1. MO2에서 `[PoE Proto] 10 Spell Registration`을 켜고 플러그인 목록에서 `PoEProtoSpells.esp`를 활성화합니다. ESP 제작에 쓴 `houseCARL - PoEProtoSpells` 폴더는 켜지 않습니다. SKSE로 새 게임이나 시험 세이브를 열고 배정 안내를 기다립니다.
2. 마법 메뉴에서 대리 주문 셋과 시험 파워가 생겼는지 봅니다. 배정 A의 표시 이름을 확인하고, 각 대리 주문을 즐겨찾기에 등록합니다.
3. **오른손 → 왼손 → 이중 시전 → 파워 → 즐겨찾기 단축키 → Wheeler → 콘솔** 순서로 시험합니다. 이중 시전은 해당 퍽을 갖춘 상태에서 같은 대리 주문을 두 손에 장착합니다. 파워는 포효 키로, 즐겨찾기와 Wheeler는 단축키나 휠로 장착한 뒤 손 시전합니다. 콘솔에서는 `player.cast <런타임 폼 ID> <대상>`을 씁니다. 대리 SPEL의 ID는 ESL 로드 순서에 따라 바뀌는 `FExxx8yy` 꼴입니다. 설치 로그·`LOADSTATE` 또는 게임 중 F7에서 해당 칸의 ID를 읽어 넣습니다. 각 경로에서 어떤 `CAST`가 나오는지 비교합니다.
4. 쿨다운이 있는 칸으로 시전하고 즉시 한 번 더 시도합니다. 두 번째 투사체가 나가는지, 매지카가 줄었는지 확인합니다. `CAST`로 엔진 비용과 관측된 매지카 차이를 비교하고, 매지카가 시전 함수보다 일찍 차감되는 경로는 HUD의 시전 전후 값도 기록합니다. 한 손과 이중 시전의 비용을 대조합니다.
5. Slot2를 장착한 채로 메뉴·콘솔을 닫고 F6으로 배정 B를 적용합니다. F7로 폼 ID와 현재 값을 확인하고, 장착을 유지한 첫 시전과 다시 장착한 뒤의 시전에서 비용과 투사체를 비교합니다. 마법 메뉴, 즐겨찾기, Wheeler, 손 HUD의 표시 이름을 메뉴를 다시 열기 전후로 비교합니다. Casting Bar 표시도 기록합니다.
6. 배정 B에서 이름이 같은 두 화염 화살(Slot1과 Slot2)을 번갈아 시전합니다. 폼 ID로 구별해 비용 20과 30, 쿨다운 0초와 2초가 칸별로 동작하는지 확인합니다.
7. 배정 B에서 저장한 뒤 같은 세이브를 불러옵니다. `LOADSTATE`의 이름·비용·시전 시간·투사체와 `HasSpell`을 다음 `APPLY`와 대조합니다. F7에서 시작 배정과 비워진 쿨다운을 확인하고, 즐겨찾기 등록이 남아 있는지 봅니다.

## 시전과 투사체 잇기

결정 90은 쿨다운 판정과 비용 차감을 거친 시전에만 피해·효과를 주고, 콘솔·스크립트 직접 시전에서는 투사체만 보이게 하는 것입니다. 이번에는 발사 때 시전 경로를 표시하고 적중 때 그 표시를 읽습니다. 피해와 효과 처리는 관찰 범위 밖입니다.

AE 1.6.1170에서 손의 발사 애니메이션 처리기(왼손 42816, 오른손 42817, 음성 42818)가 `MagicCaster::Fire`(34407)를 부릅니다. `Fire`는 가상 함수 `CheckCast`에 성공하면 `FindTargets`(34410)를 부릅니다. 그 안에서 `ActorMagicCaster`의 발사 함수(34452)가 `Projectile::Launch`(44108)를 부릅니다. 발사는 같은 스레드에서 이루어지며, 그 뒤 `Fire`가 `SpellCast(doCast=true)`를 부릅니다. `CastSpellImmediate`(34404)도 내부의 `+0xAF`에서 `FindTargets`를 부릅니다. 이 경로는 기존 vtable 0x01에서 관찰합니다.

| ID + 오프셋 또는 슬롯 | 하는 일 | 설치 확인 |
| --- | --- | --- |
| `34407+E4` | `FindTargets` 실행 동안 `inFire` 깊이를 올림 | `E8` → 34410 |
| `42816+26`, `42817+29`, `42818+5B` | 왼손·오른손·목소리 발사 처리기의 `Fire` 실행 동안 `inHandFire` 깊이를 올림 | `E8` → 34407 |
| `13723+532` | 이 자리의 `Projectile::Launch` 기록 | `E8` → 44108 |
| `13728+188` | 이 자리의 `Projectile::Launch` 기록 | `E8` → 44108 |
| `18102+E60` | `TESObjectWEAP::Fire` 쪽의 `Projectile::Launch` 기록 | `E8` → 44108 |
| `34452+354` | 주문 시전의 `Projectile::Launch` 기록 | `E8` → 44108 |
| `36419+1FC` | `ChainExplosion` 쪽의 `Projectile::Launch` 기록 | `E8` → 44108 |
| `ActorMagicCaster` vtable `0x01` (기존) | 허용된 `CastSpellImmediate` 원래 함수 실행 동안 `inImmediate` 깊이를 올림 | 기존 시전 vtable 설치 결과 |

호출 자리 검사는 AE 1.6.1170.0에서 실행합니다. `E8`의 rel32 대상과 주소 라이브러리 주소를 비교하고 설치 뒤 새 대상을 다시 읽습니다. 바이트나 대상이 다르면 그 자리의 설치를 건너뜁니다. 원래 대상과 실제 대상, 확인된 모듈 이름을 로그에 적습니다. `설치 결과: 성공 9/9 (호출 자리)`와 `성공 1/1 (미사일 적중 vtable 슬롯)`을 확인하고 결과를 판정합니다.

`LAUNCH`는 위 표의 호출 자리별로 대리 주문을 기록합니다. `LogAllPlayerSpells=true`면 플레이어가 쏜 다른 투사체도 기록합니다. 허가 열은 `inHandFire`와 `inFire`가 둘 다 0보다 클 때 `true`입니다. 곧 손·목소리 발사 처리기에서 시작한 `Fire`가 관문 `CheckCast`를 통과한 뒤 쏜 투사체만 허가합니다. 손 시전의 매지카는 차지 중에 빠지므로(2차 시험) 이 길은 비용을 낸 시전입니다. `CastSpellImmediate`(쿨다운만 보고 매지카를 빼지 않음)와 처리기가 아닌 `Fire` 호출자(`DirectlyApplySpell` 등, 비용을 빼는지 미확인)는 허가하지 않고 깊이만 기록합니다(검수 지적, 2026-11-18). 깊이들은 현재 스레드의 값입니다. `LAUNCH` 줄의 마지막 열이 `inHandFire`입니다. 반환된 핸들로 투사체 참조를 찾으면 그 폼 ID를 적습니다. 참조를 얻은 허가 투사체와 허가되지 않은 대리 주문 투사체는 핸들 값·참조 폼 ID·발사 시각으로 등록합니다. 등록은 30초 뒤 만료하며 최대 1,024개를 유지합니다.

`PHIT`는 대리 주문 미사일의 적중마다 기록합니다. 같은 참조 폼 ID의 `LAUNCH`와 맞춰 봅니다. 등록부 판정은 `authorized`, `unauthorized`, `unknown`입니다. 등록을 찾으면 발사 뒤 경과 초를 적고, 찾지 못하면 `unknown`과 `-`를 적습니다. 맞은 참조가 없으면 해당 열에 `-`를 적습니다. 한 투사체가 여러 번 맞으면 각각 기록하며, 적중 뒤에도 등록을 유지합니다.

| 시도 | 판정 기준 |
| --- | --- |
| 한 손 시전 | 투사체가 있는 대리 주문의 시전마다 `LAUNCH` 1줄이고 허가가 `true`임 |
| 이중 시전 | 실제 `LAUNCH` 수를 기록하고 각 줄의 허가가 `true`임 |
| 허가된 투사체의 적중 | 그 투사체의 `PHIT` 판정이 `authorized`임 |
| 콘솔 `player.cast` | `LAUNCH`가 없거나 발사된 줄의 허가가 `false`임 |
| 쿨다운으로 거부된 손 시전 | 그 시도의 `LAUNCH`가 0줄임 |

시험 파워는 투사체를 요구하지 않습니다. 깊이 열들은 가로챈 경로를 나타냅니다. 스크립트가 `CastSpellImmediate`를 거치면 `inImmediate`는 1이지만 허가는 `false`입니다. 콘솔과 다른 스크립트의 실제 발사 자리, 발사와 적중의 연결, 쿨다운 차단 시 발사 0건은 게임에서 확인할 항목입니다. 확인한 다섯 직접 호출 외에 간접 호출이 있을 수 있습니다. 적중이 등록보다 먼저 오거나 등록이 만료되면 판정은 `unknown`입니다.
