# 프로토타입 8: 엔진 타격의 피해를 바꾸는 자리

상태: **시험 두 번(2026-11-17). 평소 타격과 사이클론 타격 모두 피해를 바꿀 수 있고, 지우고 따로 줘도 처치는 플레이어에게 감. 남은 것은 큐로 미뤄진 플레이어 타격(Q2) 하나.** 지금 배치된 것은 모드 키를 F3으로 옮긴 빌드(2026-11-17 21:58). 아래의 "물을 것"과 "판정 기준"은 돌리기 전에 적은 것입니다.

설계-현황 5장 40번의 (2)·(3)을 위한 시험입니다. (2)는 사이클론처럼 엔진의 근접 타격으로 주는 스킬에서 엔진이 계산한 무기 피해를 우리 값으로 바꿀 수 있는가, (3)은 받는 피해 쪽의 환산을 어디에 걸 수 있는가입니다. 저장소의 서브모듈 `external/CommonLibSSE-NG`(v16.4.0, 결정 60)로 빌드합니다.

## 배경 (실행 전, 디컴파일로 읽은 것)

자세한 것은 설계-현황 4.6의 "엔진 타격의 피해가 체력에 이르는 길"(2026-11-15). 요약:

- 근접 타격 함수(AE ID 38627)가 타격 자료(`RE::HitData`)를 채운 뒤, 시작에서 +0x4A8 자리에서 `HitData` 적용 함수(AE ID 38586)를 `(대상, &hitData)`로 부릅니다. 화살도 38627을 지납니다.
- 38586은 적중 이벤트를 보내고 `HitData.totalDamage`(+0x50)를 `Actor::DoDamage`로 체력에 적용합니다. 난이도 배율은 `DoDamage` 안에서 곱해지므로 `totalDamage`는 배율 전의 값입니다.
- 38586은 다른 스레드에서 불리면 `HitData`를 복사해 작업 큐에 넣고 돌아갑니다. 나중에 작업 큐(AE ID 36991 `BSTaskPool_HandleTask`의 +0xA3D)가 그 복사본으로 38586을 다시 부릅니다.
- 프로토타입 7의 첫 측정(2026-11-14): 체력 피해 함수(가상 함수 0x104)는 체력이 깎인 뒤에 불려서 피해를 바꿀 수 없었습니다. 피해가 여러 스레드에서 왔습니다.

그래서 이 프로토타입은 38627 +0x4A8의 호출을 가로채, 원래 함수를 부르기 전에 `totalDamage`를 바꿔 봅니다. 작업 큐가 다시 부르는 자리는 보기만 합니다(바꾸면 같은 타격을 두 번 고침).

## 1차 시험 (2026-11-17 21:11~21:19)

사용자가 게임을 한 번 켜고 `observe`(관찰) → `set`(바꾸기, Value 10) → `zero`(지우기) 순으로 해 봄. `replace`(대신 주기)는 하지 않음. 로그 사본은 `out/test1/`(저장소에 넣지 않음), 분석은 `python tools\analyze_hits.py out\test1\PoEProtoHitDamage.log --skill out\test1\PoEProtoSkillInput.log`. 튕기지 않았고 그 뒤 크래시 로그도 없음. 프로토타입 2와 7, 프렌지 모드, Precision이 함께 켜져 있었음.

**설치**: 런타임 1.6.1170, 두 자리 모두 가로챔. **근접 타격 자리는 이미 `FollowerScaling.dll`이 가로채고 있었고**, 계획대로 그 위에 겹쳐 설치함(부르는 순서: 이 플러그인 → FollowerScaling → 38586). 바꾼 플레이어의 타격 값은 FollowerScaling을 지나도 그대로였음(Q1).

| 물음 | 결과 | 근거 |
| --- | --- | --- |
| Q1 바꾸면 체력이 V × 배율만큼 주는가 | **그렇다** | `set`에서 플레이어의 근접 타격 39번 모두 체력이 정확히 6.0(= 10 × 0.6) 줄었고 모두 원래 함수 안에서 줄었음. 바꾸기 전 값은 13.6~73.1로 제각각 |
| Q2 큐로 미뤄진 타격 | 판정하지 않음 | `set`에서 큐로 미뤄진 플레이어 타격이 없었음(근접 자리 기록의 대부분이 한 스레드에서 옴). 대신 NPC의 화살 한 번이 미뤄졌는데, 근접 자리에서는 체력이 그대로였고 큐가 다시 부를 때 같은 값(160.4)으로 한 번만 160.4 × 0.6 = 96.24가 깎임. 미루는 길이 디컴파일대로 도는 것은 봄 |

| Q4 칸들의 관계 | 일부 | 막기와 방어구가 `totalDamage`에 이미 들어 있음: 플레이어가 맞은 타격에서 `total ÷ physical`이 막지 않으면 0.458, 10% 막으면 0.412(= 0.458 × 0.9). 즉 `total = physical × 방어 계수 × (1 − percentBlocked)` 꼴. 그러니 `set`처럼 값을 통째로 바꾸면 방어구와 막기로 줄어든 몫이 사라지므로, 우리 값에 `(1 − percentBlocked)`와 우리 방어 계산을 다시 걸어야 함. 은신 공격 기록은 없음(`sneakAttackBonus`가 늘 1). `reflectedDamage`는 늘 0, `bonusHealthDamageMult`는 늘 1 |

**함께 확인된 것**
- 엔진의 난이도 배율 규칙(설계-현황 4.6, 디컴파일로 읽은 것)이 실행으로도 맞음: 플레이어가 끼지 않은 NPC끼리의 타격 119번 가운데 95번이 정확히 `total × 주는 배율 0.6`만큼 줄었음(나머지는 체력이 −30에서 멈추거나 그 사이 회복된 것).
- `observe`의 플레이어 타격 61번 가운데 31번은 `totalDamage`가 0이었음. 대상 대부분이 체력이 −30 근처에서 멈춘 필수 NPC(도시 주민)였음. 원인은 가리지 않음.
- 프로토타입 2의 사이클론은 프렌지가 켜져 있어 양보했고, 사이클론 타격은 이번 시험에 없었음. 사이클론의 DLL 타격을 이 자리에서 바꿀 수 있는지는 아직 모름.

## 플러그인이 하는 일

`PoEProtoHitDamage.dll`. 게임에 아무것도 놓지 않습니다.

- **가로채기**: 근접 타격 함수(AE ID 38627)의 +0x4A8 호출과 작업 큐(AE ID 36991)의 +0xA3D 호출. 런타임이 자리를 확인한 판(AE 1.6.1170)이 아니면 아무것도 설치하지 않습니다(다른 판에서는 오프셋이 명령 중간을 가리킬 수 있음). 설치하기 전에 그 자리가 정말 38586을 부르는 `call`인지 바이트로 확인합니다. 호출 대상이 38586이 아니면, 다른 모드의 가로채기로 보일 때만(실행할 수 있는 메모리이고, 다른 DLL 안이거나 SKSE 분기 풀의 `jmp [rip+0]`이 다른 DLL로 감) 그 DLL의 이름을 로그에 적고 그 위에 겹쳐 설치합니다(그 모드는 우리가 바꾼 값을 받음). 그 밖이면 설치하지 않습니다.
- **모드**(F3으로 차례로 바꿈, 화면에 알림. 2차 시험까지는 F8이었음):
  - `observe`(관찰): 바꾸지 않고 적기만 함. 처음 모드.
  - `set`(바꾸기): `totalDamage`를 `Value`로.
  - `zero`(지우기): `totalDamage`를 0으로.
  - `replace`(대신 주기): `totalDamage`를 0으로 하고, 원래 함수가 끝난 뒤 대상에게 `DoDamage(Value, 공격자)`를 따로 줌.
  - 바꾸는 것은 공격자가 플레이어인 타격만(`Scope = player`). `Scope = all`이면 모든 타격.
- **적는 것**(`PoEProtoHitDamage.log`): 가로챈 호출마다 자리(`melee`/`queue`), 모드, 스레드, 공격자, 대상, 무기, 투사체(`sourceRef`), `HitData`의 표시와 피해 칸들, 바꾸기 전과 뒤의 `totalDamage`, 원래 함수 앞뒤의 대상 체력, 그때의 난이도 배율. 원래 함수 안에서 체력이 줄지 않았는데 피해가 0보다 크면 다음 프레임에 체력을 다시 읽어 늦은 읽기로 적습니다. 플레이어가 끼인 적중 이벤트와 모든 사망 이벤트도 적습니다.

원래 함수는 어떤 모드에서든 정확히 한 번 부릅니다. 앞뒤의 기록에서 오류가 나도 원래 함수는 부릅니다.

## 로그의 형식

줄마다 맨 앞이 종류이고 칸은 탭으로 나눕니다. 시각은 플러그인이 올라온 뒤의 마이크로초.

| 종류 | 칸 |
| --- | --- |
| `HIT` | 시각, 스레드, 자리, 모드, 바꿨는지(0/1), 공격자, 대상, 무기, 투사체 참조, 투사체 참조의 폼 종류, 표시(16진), 바꾸기 전 `totalDamage`, 바꾼 뒤 `totalDamage`, `physicalDamage`, `percentBlocked`, `resistedPhysicalDamage`, `resistedTypedDamage`, +0x6C 칸(CommonLibSSE-NG의 이름 `sneakAttackBonus`. 은신 타격에서도 1.0이었음), +0x70 칸(은신 배율. CommonLibSSE-NG의 이름 `bonusHealthDamageMult`), `reflectedDamage`, `stagger`, 호출 전 체력, 호출 뒤 체력, 최대 체력, 그때의 배율(대상이 플레이어면 받는 배율, 아니면 공격자가 누구든 주는 배율. 엔진의 `GetDifficultyMultiplier`(AE ID 26503)를 디컴파일로 읽은 규칙) |
| `OWN` | 시각, 스레드, 대상, 준 값, 준 뒤 체력, 죽었는지 (`replace` 모드에서 따로 준 피해) |
| `LATE` | 시각, 대상, 다시 읽은 체력, 그 앞 `HIT` 줄의 시각 |
| `EVHIT` | 시각, 스레드, 대상, 가해자, 수단 폼, 투사체 폼, 표시 (플레이어가 대상이거나 가해자인 적중 이벤트) |
| `EVDEATH` | 시각, 죽는 액터, 죽인 액터, 끝났는지 |
| `MODE` | 시각, 새 모드 |

`HitData`의 표시: 1 막힘, 2 무기로 막음, 8 치명타, 0x800 은신 공격, 0x4000 방패 치기, 0x10000 강공격, 0x20000 왼손, 0x40000 근접, 0x100000 폭발(CommonLibSSE-NG의 `HitData::Flag`).

## 시험하는 법 (배치한 뒤)

1. 프로토타입 7(`[PoE Proto] 7 Measure`)은 끄는 편이 좋습니다. 켜 두면 피해를 바꾼 타격이 7의 측정 기록에 섞입니다.
2. MO2에서 `[PoE Proto] 8 Hit Damage`를 켜고 게임에 들어가면 "[PoE Proto 8] 관찰 모드. F3 키로 바꿈"이 뜹니다.
3. 아무 적이나 상대로(화이트런 근처의 늑대나 산적이면 충분):
   - `observe`: 일반 공격, 강공격, 은신 공격을 몇 번씩. 적이 나를 몇 번 치게 둠. 방패나 무기로 막아 보기. 활이 있으면 몇 발.
   - F3 → `set`: 몇 번 침(Value가 10이면 난이도 배율 0.6에서 한 번에 6씩 줄어야 함).
   - F3 → `zero`: 몇 번 침. 적이 움찔하는지, 피해가 없는지 봄.
   - F3 → `replace`: 적 하나를 끝까지 잡음.
4. 끝나면 알려 주세요. `PoEProtoHitDamage.log`를 먼저 복사하고 읽습니다.

튕기면: 게임에 들어가기 전이면 설치(바이트 확인, 가로채기)를, 타격하는 순간이면 가로챈 함수 안을 의심합니다. 크래시 로그의 호출 스택에 `PoEProtoHitDamage.dll`이 있는지부터 봅니다. INI의 `HookQueue = false`로 작업 큐 쪽 가로채기만 끌 수 있습니다.

## 설정 (`PoEProtoHitDamage.ini`)

| 키 | 기본 | 뜻 |
| --- | --- | --- |
| `ModeKey` | `0x3D`(F3) | 모드를 바꾸는 키의 DirectInput 스캔 코드. 0이면 쓰지 않음 |
| `StartMode` | `observe` | 처음 모드(`observe`, `set`, `zero`, `replace`) |
| `Value` | `10.0` | `set`과 `replace`에서 쓸 값(난이도 배율 전). 0 이상 10000 이하 |
| `Scope` | `player` | `player`: 공격자가 플레이어인 타격만 바꿈. `all`: 모든 타격 |
| `HookQueue` | `true` | 작업 큐가 다시 부르는 자리도 가로채서 적음(바꾸지는 않음) |
| `Notify` | `true` | 게임에 들어갔을 때와 모드를 바꿀 때 화면에 알림 |

## 실행으로 확인하지 않은 전제

- 38627 +0x4A8과 36991 +0xA3D가 38586을 부르는 자리라는 것은 AE 1.6.1170의 디컴파일과 바이트 검색으로 본 것입니다. 플러그인이 설치 전에 판과 바이트로 다시 확인합니다.
- 다른 모드가 같은 자리를 가로챘을 때 겹쳐 설치하는 길은 이 모드 목록에 그런 모드가 있어야 돌아서, 돌려 보기 전에는 확인할 수 없습니다.
- 38586의 두 인자가 (대상 `Actor*`, `HitData*`)이고 `HitData`의 배치가 CommonLibSSE-NG v16.4.0의 `RE::HitData`(크기 0x90, `totalDamage` +0x50)와 같다는 것. +0x50은 디컴파일에서 `DoDamage`에 넘기는 값으로 확인했고, 나머지 칸은 헤더를 믿습니다.
- 가로챈 함수가 여러 스레드에서 불릴 때 대상의 체력을 읽고 `DoDamage`를 부르는 것이 안전하다는 것. 엔진도 같은 스레드에서 `DoDamage`를 부르지만, 그것으로 안전이 확인된 것은 아닙니다.
- F3이 이 모드 목록의 다른 모드와 겹치지 않는다는 것. 처음의 F8은 프로토타입 2의 `TestStaggerKey`(0x42)와 겹쳤음(2차 시험에서 F8을 누르자 프로토타입 2가 플레이어에게 경직 시험을 걸었음). 배치된 프로토타입들의 INI가 쓰는 키(F4, F6, F7, F8, F10, F11)는 피했음.
