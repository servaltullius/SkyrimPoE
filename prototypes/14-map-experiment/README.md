# 프로토타입 14: 지도 팩 실험 (6단계 재작업 실험 단계 E)

6단계 재작업 계획(`docs/6단계-재작업-계획.md`) 3장의 위험 관문 G-1~G-7을 구현 전에 실험으로 가린다.
- 6단계 브랜치의 정리 경로는 쓰지 않는다. 특히 같은 작업 안에서 `Disable()`과 `SetDelete(true)`를 잇달아 부르는 코드가 없다.
- 지도 팩은 R1 도구(`tools/dungeon-clone`)가 만든 `SkyrimPoE_Maps.esp`와 목록 파일 `SkyrimPoE_Maps.json`을 쓴다.

## 실행

- **표지 파일**: SKSE 로그 폴더(`Documents\My Games\Skyrim Special Edition\SKSE\`)에 `PoEProtoMapExperiment.autotest`를 둔다. 첫 줄은 불러올 세이브 이름이다. MO2의 SKSE로 게임을 켜면 시험을 돌린다.
- **표지 파일이 없으면** 아무것도 하지 않는다.
- **결과 파일**: 같은 폴더의 `PoEProtoMapExperiment.log`(기록)와 `.tsv`(판정 표)
- **설정**: `Data/SKSE/Plugins/PoEProtoMapExperiment.ini`
  - `QuitWhenDone`
  - `Cycles`(G-1 회수)
  - `TourDungeon`(G-5로 남을 던전 키)
- **설치**: 지도 팩 `SkyrimPoE_Maps.esp`와 `SkyrimPoE_Maps.json`을 DLL과 함께 MO2 모드 폴더 `[PoE Proto] 14 Map Experiment`에 둔다. 모드와 플러그인은 사용자가 켠다(MO2가 켜진 동안 설정 파일을 직접 고치지 않음).
- **스폰 원형**: `LvlBanditMelee1H`(`03DECB`). 실험용이고 결정 170의 원형 정책과는 관계없다.
- **무적**: 시험 동안 플레이어는 `SetGodMode(true)`로 무적이다. 끝에 처음 상태로 되돌린다.
- **세이브**: 실내에 있는 세이브여야 한다. 아니면 시험을 멈춘다.
- **입장 실패**: 어떤 블록에서 입장에 실패하면 그 블록의 스폰·전투·측정 단계를 건너뛴다. 귀환·정리·기록 단계는 그대로 한다.

## 한계

- 정해진 세이브 하나와 이 모드 목록에서 본 결과다.
- 경로 판정은 AI 추격 거리로 어림한 것이다. 사람이 걷는 경로와 같지 않다.
- `Cell.Reset()`이 언제, 무엇을 되돌리는지는 이 실험이 보는 범위(우리 스폰, 시체, 문 하나의 열림)만 기록한다. 호출 결과를 받는 콜백이 없어서, 호출을 보냈다는 것만 알고 실행됐는지는 모른다. 셀이 떨어져도 버퍼에 남아 있으면 "다음 로드"가 오지 않을 수 있다.
- 목록 파일의 `espSha256`은 확인하지 않는다(런타임 R4의 일).
- 야외 귀환은 저장한 야외 셀이 조회되면 그 셀을 넘긴다. 셀 없이 월드스페이스만 넘기는 경로는 시험하지 않는다.

- 셀 떨어짐 대기의 "0ms"는 귀환이 끝난 뒤의 첫 검사에서 `IsAttached()`(상태가 정확히 attached인지)가 이미 false였다는 뜻이다. 버퍼에서 완전히 내려갔는지는 모른다. (b)의 "3초"는 틱 수가 아니라 실제 시간이다.
